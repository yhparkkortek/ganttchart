# 🤖 AI 자율 하네스 환경 — 설계 노트 (2026-10-30)

SAP·그룹웨어 제어를 붙이면서 얻은 것을 **"AI가 이 일을 혼자 돌게 하려면 무엇이 있어야 하나"**로
다시 정리한 문서. 사내 발표를 준비하며 나눈 대화에서 나왔다.

> **핵심 전제: 자율성은 모델의 능력이 아니라 환경의 성질이다.**
> 같은 AI라도 환경이 없으면 몇 수 만에 헤매고, 환경이 깔려 있으면 혼자 끝까지 간다.
> 그래서 "더 좋은 모델을 쓴다"가 아니라 "환경을 깐다"가 답이었다.

AI는 **매 세션 기억을 잃고 오는 신입**이다. 환경을 만든다는 건 그 신입이 혼자 일할 수 있게
사무실을 차려 주는 일이다.

## 1. 하네스 여섯 부품

| | 부품 | 하는 일 | 이 저장소의 실물 | 없으면 |
|---|---|---|---|---|
| ① | **지도** | 매 세션 자동으로 읽히는 것 | `CLAUDE.md` + `docs/` | js 79개를 매번 grep으로 훑는다 |
| ② | **눈** | AI가 직접 부르는 관찰 수단 | `/sap-dump-screen` · CDP 캡처 · `node --check` | 추측한다 |
| ③ | **관문** | 기계가 막는 것 | `.claude/settings.json` 훅 4개 | 틀린 게 그냥 나간다 |
| ④ | **기록** | 실패가 데이터로 남는 곳 | `_issueLog` · 시그니처 군집 · 도구 호출 로그 | 같은 실수를 반복한다 |
| ⑤ | **바닥** | 되돌릴 수 있음 | git · 스크래치패드 · `dry_run` | 겁나서 아무것도 못 시킨다 |
| ⑥ | **분업** | 역할 나눈 여러 창 | 조사 / 구현 / 검토 | 서로 덮어쓴다 |

### ① 지도 — 읽을 것을 파일로

- `CLAUDE.md`는 **매 세션 통째로 로드된다.** 그래서 여기엔 **색인만** — 비대해지면 토큰이 샌다.
- 상세는 `docs/` 주제별로, 색인에 "이 작업 할 때만 읽을 것"으로 표시.
- **가장 값진 항목은 기능 설명이 아니라 함정(실패 이력)이다.** 예: "PowerShell로 HTML 고치지 마라",
  "`/LOC` 레이아웃 쓰지 마라", "`docBodyContent`는 본문이 아니다". 적어 두면 다음 세션이 안 겪는다.
- 갱신 경로: 사고가 나면 → `docs/`에 원인+재발방지 → `CLAUDE.md`에 한 줄.
  PreCompact 훅이 압축 직전에 "새 규칙을 지도에 반영하라"고 자동 지시한다.

### ② 눈 — 스스로 관찰할 수단

원칙 세 가지:
1. **부작용이 없어야** AI가 마음껏 쓴다. 뭔가를 바꿀 수 있으면 조심스러워지고, 조심스러우면 **추측한다.**
2. **한 번에 끝나야** 한다(사람 개입 없이).
3. **구조화해서** 줘야 한다. 화면 글자를 통째로 넘겼더니 **없는 납기일·제조사를 지어냈다**
   → `/sap-material-rows`처럼 컬럼으로 분리.

근거: 그룹웨어 통신 주소를 **추측 12개 전부 404**, 관찰 한 번에 확정.
SAP 고정 대기가 **215곳 합계 171.8초**였는데 실측해 보니 명령은 0.13~0.17초에 이미 끝나 있었다.

### ③ 관문 — 기계가 막는다 (자율의 전제조건)

`.claude/settings.json`:

| 이벤트 | 검사 | 결과 |
|---|---|---|
| `PreToolUse`(Bash) | `git commit`인데 `origin/main`보다 뒤처졌나 | **차단** + 되돌아갈 파일 목록 |
| `PreToolUse`(Bash) | 커밋 전 js 79개 문법 검사 (0.6초) | 오류면 **차단** |
| `PostToolUse`(Edit\|Write) | 백엔드 파일이 바뀌었나 | 배포 zip **자동 재생성** |
| `PreCompact` | 압축 직전 | 지도 갱신 지시 |

**교훈: 규칙은 말로 적지 말고 기계로 막아라.** `CLAUDE.md`에 "커밋 전 fetch하라"고 적어 뒀는데도
**하루에 두 번** 사고가 났다(손 안 댄 파일이 194줄·236줄 과거로 되돌아감, 문법 오류가 없어 둘 다 조용히 통과).
훅을 깐 뒤로는 안 난다.

⚠️ **관문도 고장 난다.** 2026-10-29 `gw_bridge.py`를 고쳤는데 zip 자동 재생성이 **조용히 안 돌아**
수동으로 재압축했다. 관문이 돌았는지도 가끔 확인해야 한다.

### ④ 기록 · ⑤ 바닥

- 실패를 **조용히 삼키지 않는다**(`except: pass` 금지). 시그니처로 **묶어서** 센다 —
  "몇 번 났는가"가 보여야 고칠 값어치가 판단된다.
- 되돌릴 수 있어야 **과감하게 시킨다.** 실제로 기안 작성 화면에 본문을 주입 → 되읽어 확인 →
  원래 값 복구 → **저장 안 함**으로 실환경 검증을 했다. 되돌릴 수 없었으면 엄두를 못 냈다.

### ⑥ 분업 — 여러 AI 창

- 역할: **조사**(읽기만, 싼 모델) / **구현** / **검토**(만든 쪽과 보는 쪽 분리).
- ⚠️ **가장 자주 깨지는 지점: 같은 폴더를 둘이 건드릴 때.** 2026-10-29에도 다른 세션이 고치던
  `sap_bridge_32.py`가 배포 zip에 섞여 들어갈 뻔해 `git show HEAD:` 로 따로 빼서 재압축했다.
- 규칙: 같은 파일을 둘이 건드리지 않는다 · 작업 공간을 나눈다 · **합치는 지점은 git 하나로.**

## 2. 자가진단 — 우리는 어디까지 왔나 (2026-10-30)

| 부품 | 상태 | 근거 |
|---|---|---|

| ④ 기록 | **절반** | 앱 런타임은 좋음. **개발 과정의 실패는 수동 기록** |

## 3. 검증 실패를 극복하는 법

관문은 **기계적 사실**(문법이 맞나, 뒤처졌나)만 안다. **"원하신 대로 동작하나"는 모른다.**
그걸 기계가 알려면 받아들임 조건을 **미리 적어 둬야** 한다.

규칙 네 줄은 `CLAUDE.md` "✅ 「고쳤다」의 정의" 절에 박아 뒀다(커밋 `5ef9993`). 요지:

1. 증거는 **사람이 실제로 지나는 경로**를 통과한 것. 부품 단위 호출은 증거가 아니다.
2. 못 돌렸으면 **못 돌렸다고 먼저 쓴다** — "확인한 것 / 확인 못 한 것".
3. 못 돌리는 건 생략 사유가 아니라 **하네스를 만들 사유.** 가짜는 **경계에만**.
4. 같은 검증을 두 번 만들었으면 **파일로 남긴다.**

### 왜 이 규칙이 생겼나

2026-10-29 칩 표 사고에서, 렌더러만 직접 불러 "표가 그려진다"를 확인하고 **고쳤다고 보고**했다.
깨져 있던 건 루프→`calls`→부착부 **연결**이라 그 테스트로는 절대 안 잡혔다.
**빠진 건 지식이 아니라 고백이었다** — "루프 전체는 못 돌렸다" 한 줄만 썼어도 즉시 잡혔다.

그리고 첫 재현 실패는 **가짜 실패**였다(스텁이 호출 **순서**로 분기했는데 다른 경로가 첫 호출을 먹음).
→ **스텁은 호출 순서에 기대지 않게 만들 것.** 실패가 나면 "코드가 틀렸나, 테스트가 틀렸나"부터 가른다.

## 4. 앱 안의 실행 루프 — 설계 (미구현)

### ⚠️ 두 루프를 섞지 말 것

| | **실행 루프**(런타임) | **수정 루프**(개발) |
|---|---|---|
| 무엇이 잘못됐나 | 데이터·상태 (칸을 못 찾음, 값이 빔) | 코드 |
| 누가 고치나 | 앱 안의 AI(Gemini) | 개발 세션(Claude Code) |
| 고치는 것 | 입력값·양식 선택·재조회 | 소스 파일 |
| 앱 안에서 되나 | **된다** | **안 된다** |

앱은 자기 소스를 못 고친다. 앱이 할 수 있는 건 **구조화된 신고**까지 — 그걸 받아 개발 루프가 고친다.
둘을 잇는 게 ④ 기록(Phase 10)이다.

### 실행 루프의 모양

```
1. 사람      "그 문서 틀로 지금 프로젝트 기안 작성해줘"
2. AI        어떤 양식·어떤 문서를 틀로 쓸지 고른다        ← 해석은 AI
3. 코드      읽고 → 채우고 → 되읽어 판정                  ← 실행·검증은 코드
4. 판정 실패
   ├ 값 문제  "이 칸들이 비었다. 후보 중 뭘 넣을까" → AI 재질의 → 3 (상한 N회)
   └ 구조 문제 "에디터를 못 찾음 / 통신 404"       → 재시도 금지, 신고하고 멈춤
5. N회 초과  사람에게 "여기까지 됐고 이게 안 된다" + 증거
```

**원칙: AI에게 판정을 맡기지 말고 후보를 고르게 하라. 판정은 코드.**
프롬프트로 "확인해 줘"라고 하면 **자기가 만든 결과를 자기가 본다** — 위의 사고와 같은 구조다.

판정의 실물은 이미 있다 — `approval_draft`가 넣고 **되읽어서** 찍는 로그:
`{field:'본문', id:'editorForm_5', len:44043, ok:true}`

### ⚠️ 무한 반복 금지

- 상한 없이 자동 판정을 돌렸다가 **한 스윕 76연발로 하루 AI 한도를 태운** 적 있다(2026-10-21).
- 로그인은 **재시도하면 계정이 잠긴다** — 1회로 막아 뒀다.
- 같은 실패는 반복해도 같은 결과다.

→ **상한 + 실패 종류 구분 + 사람에게 넘기는 출구**가 루프의 필수 부품이다.

### 이미 있는 조각

판정 함수(`approval_draft`의 `log`) · 사람에게 설명(`approval_copy`의 `notes`) ·
재시도 엔진(Phase 4) · 실패 기록(Phase 10).
**없는 건 "판정 실패 → 재질의 → 재실행"의 연결과 상한뿐이다.**

## 5. 그래서 사람의 자리는

"사람이 계속 모니터링한다"는 하나가 아니라 **네 개의 서로 다른 일**이다.

| 사람이 한 일 | AI가 왜 못 했나 | 자동화 경로 |
|---|---|---|
| **결과 수용 판정** ("개선이 안 되었는데?") | 기준을 **AI가 정했다** → 자기가 통과시킴 | 수용 조건을 **미리 못 박기**(테스트) ← 지금 0 |
| **남의 변경 판단** ("그대로 두기") | 어느 변경이 누구 것인지 모름 | **작업 공간 분리** → 문제 자체가 소멸 |
| **무엇이 이상한지 눈치채기** | 업무 맥락은 사람만 앎 | 어려움. 사용 로그로 일부만 |
| **환경 조작**(백엔드 재시작) | **일부러 막아 둠**(예약발송·SAP 작업이 날아감) | 무중단 재적재 설계 |

> **목표 상태: 사람은 "맞나 틀리나"를 보지 않고 "할까 말까"만 고른다 — 검사원에서 승인자로.**

완전히 대체되지는 않으며, 그게 설계다. 되돌릴 수 없는 일(상신·발송·삭제·계정 잠김 위험)은
일부러 사람에게 남겼다.
