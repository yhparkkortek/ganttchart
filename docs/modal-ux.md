# 🪟 모달 이동·크기조절·테두리 (`js/19-shared-modal-drag.js`)

**읽을 때**: 모달을 끌거나 크기를 바꾸는 동작이 이상할 때, 새 모달에 그 동작을 붙일 때,
"창 크기를 바꿨는데 모달이 화면 밖에 있다"는 제보를 받았을 때.

모달 25개+가 이 파일 하나를 공유한다. 여기 한 곳을 고치면 전부 바뀌고, **여기서 틀리면 전부 틀린다.**
아래는 2026-10-21~22 실사용 제보를 하나씩 계측해서 잡은 기록이다 —
전부 "코드가 없어서"가 아니라 **"있는데 서로 싸워서"** 생긴 문제였다.

## 붙는 방식

`_makeDraggable(modalId, handleId)` 하나를 부르면 세 가지가 자동으로 딸려 온다:

| 함수 | 역할 |
|---|---|
| `_makeMinimizable` | 최소화(하단 taskbar) |
| `_makeResizable(modalId, false, handleId)` | 8방향 크기조절 + 테두리 + 화면 안 보정 |
| `_installModalResizeHost()` | 모달 **바깥 링**을 받는 전역 핸들러(한 번만 설치) |

`_makeDraggable` 을 안 거치는 모달은 `RESIZABLE_EXTRA_MODALS`(데이터, js/19 끝)에 id 만 적는다.

## ⚠️ 잡는 띠 — 테두리가 **한가운데**다

```
EDGE_OUT = 13   // 박스 바깥
EDGE_IN  = 13   // 박스 안쪽
```

**보이는 테두리가 아니라 투명한 판정 영역이다.** 그려지는 것이 없다.

- 바깥 절반이 필요한 이유: **안쪽 절반은 스크롤바에 덮인다.** 윈도우 크롬의 고전 스크롤바는
  15px 자리를 실제로 차지하고, **그 위를 누르면 페이지에 `mousedown` 이 오지 않는다** —
  리사이즈가 영영 시작되지 않는다. (개발용 브라우저는 오버레이 스크롤바라 폭이 0이어서
  **재현이 안 된다**. "제 환경에선 되는데요"가 나오면 스크롤바부터 의심할 것.)
- 안쪽 절반이 필요한 이유: 화면 가장자리에 붙은 모달은 바깥쪽이 화면 밖이라 못 잡는다.
- 비대칭으로 두면("바깥 16 / 안쪽 10") 사람은 **테두리를 잡는다고 생각하는데 손이 빗나간다.**
  대칭이어야 손이 가는 곳과 잡히는 곳이 일치한다.

## ⚠️ 한 번 누르면 **하나만** 시작해야 한다

헤더 높이는 55px 쯤인데 그 **위쪽 13px 이 리사이즈 띠와 겹친다**. 사람은 헤더 위쪽을 잡는다.
그래서 예전엔 헤더를 잡으면 **드래그와 리사이즈가 동시에** 걸렸고, 둘이 매 프레임 같은
`left/top/height` 를 서로 다르게 써서 "끌면 어색하다"가 됐다(실측: 상단+3px·+10px 에서 둘 다 켜짐).

→ **모달 안쪽에서는 헤더가 이긴다**(`isInteractive` 가 헤더를 버튼과 같이 취급해 양보).
  위쪽 변 리사이즈는 모달 **바깥** 절반에서 한다 — 바깥엔 헤더가 없다.

누른 지점별 기대 동작(회귀 시험 기준):

| 지점 | 시작되는 것 |
|---|---|
| 헤더 안 (상단+3 / +10 / +30px) | 드래그만 |
| 모달 밖 (상단-6 / 왼쪽-6px) | 리사이즈만 |
| 모달 안 왼쪽 +6px (헤더 아님) | 리사이즈만 |
| 모달 안 버튼 위 | 아무것도 안 함(클릭이 최우선) |

## ⚠️ 커서는 `<html>` 클래스 + `!important` 로

`document.body.style.cursor` 로 칠하면 **자기 커서를 가진 요소 위에서는 무시된다**
(`cursor` 는 상속 속성이라 `cursor:auto` 인 곳에만 내려간다). 모달 밖은 오버레이·표 영역 등이
깔려 있어 **바뀌는 자리와 안 바뀌는 자리가 섞였고**, 그게 "반응이 느리다"로 느껴졌다.

→ `_mreszSetCursor(cur)` 가 `<html>` 에 `mresz-ew-resize` 같은 클래스를 걸고
  `html.mresz-X, html.mresz-X * { cursor: X !important }` 로 **전부 덮는다**(드래그·리사이즈의 표준 방식).
  실측: 자체 커서를 가진 `#gantt-table-scroll` 위에서도 바뀐다.

## ⚠️ 드래그 중에는 다들 비켜야 한다

드래그는 매 프레임 `style.left/top` 을 쓴다. 그런데 모달마다 `style` 속성을 보는
MutationObserver 가 걸려 있어(열릴 때 화면 안으로 들이려고) **그 쓰기마다 깨어나 레이아웃을
다시 재고 테두리 색까지 다시 계산**했다 — 실측 마우스 이동 25회에 clamp 25회.

→ `window._mreszDragging` 플래그로 **드래그 중에만** 쉰다:
  - `onShown`(관찰자) 즉시 반환
  - 전역 호스트 mousemove 즉시 반환(등록된 모달 13개를 훑지 않는다)
  - 박스 mousemove 즉시 반환(안 그러면 `ns-resize` 가 `grabbing` 을 덮어 깜빡인다)

실측: 이동 25회 동안 clamp 0회·테두리 재계산 0회.

## ⚠️ 놓을 때 되돌리지 말 것

드래그에는 **자기 규칙**이 있다 — `DRAG_MARGIN`(40px)만 남으면 일부러 화면 밖으로 내보낼 수 있다.
그런데 `_clampModalToViewport` 는 **전부** 안으로 들인다. 놓을 때 그걸 부르면 가장자리까지
끌고 간 모달이 **손을 떼는 순간 되튄다**. 두 규칙이 싸우면 사람이 둔 자리가 안 지켜진다.
→ 화면 안으로 들이는 일은 **"창 크기가 바뀌어 모달이 안 보이게 될 때"만** 한다.

## 🐛 `offsetParent` 로 "보이는가"를 판정하지 말 것

**`offsetParent` 는 `position:fixed` 요소에서 항상 `null`이다.** 이 앱의 모달은 전부 fixed 라,
그 판정을 쓰던 화면-안-보정이 **한 번도 돈 적이 없었다**(기능이 있는 줄 알았는데 없었다).
실측: resize 이벤트 한 번에 옛 판정으로는 통과 모달 **0개**.

→ `_mreszIsShown(el)` 을 쓴다(크기 0 아님 + `display`/`visibility` 확인).

## 🎨 테두리 = 그 모달 **헤더의 아래 경계선 색**

헤더 **배경**이 아니다. 실측:

| 모달 | 헤더 배경 | 헤더 아래선 ← 테두리 |
|---|---|---|
| 기안 작성(js/47) | `#e7f3ff` | `#a5c8f0` |
| 공지·팔레트·알람 | `#fff8e6` | `#ffe08a` |

배경을 쓰면 테두리가 헤더보다 연해서 **틀로 안 보인다**. 아래선을 쓰면 모달마다 자기 헤더와
한 벌인 틀이 된다. 굵기는 1px(`.mresz-modal` 공통 규칙), **색만** 인라인으로 칠한다(`!important` —
모달 상당수가 인라인 style 로 자기 테두리를 갖고 있다).

⚠️ 색이 **계산값**이라 CSS 변수처럼 저절로 안 따라간다 → 팔레트가 바뀌면 다시 칠해야 한다.
js/21 이 팔레트를 적용할 때마다 `<style id="cp-live-style">` 내용을 갈아끼우므로 그걸
MutationObserver 로 지켜보다 60ms 묶어 다시 칠한다(js/21 을 건드리지 않아도 된다).
모달이 **열릴 때도** 다시 읽는다 — 숨어 있으면 색을 못 읽고, 헤더가 그때 그려지는 모달이 있다.

## ⚡ 쓰기는 프레임당 한 번 (rAF)

이동은 위치만 바뀌지만 **크기 변경은 모달 내용 전체가 다시 배치**된다. 브라우저는 `mousemove` 를
프레임보다 자주 줄 수 있어서, 이동마다 바로 쓰면 한 프레임에 레이아웃이 여러 번 돈다.
→ 좌표만 받아 두고 `requestAnimationFrame` 으로 묶는다(마지막 좌표를 쓰므로 정확도는 그대로).
실측: 마우스 이동 20회 → 실제 `style.width` 쓰기 8회, 폭 궤적은 기대값과 오차 0.

## 🧪 이 파일을 고친 뒤 확인할 것

브라우저에서 **진짜 마우스**로(합성 이벤트는 `e.target` 이 달라 결과가 다르다):

1. 헤더로 끌기 → 요청한 만큼 1:1 로 따라오는가, 크기가 안 변하는가
2. 네 변 + 모서리 바깥에서 리사이즈 → 되는가, 축소도 되는가
3. 모달 안 버튼 클릭 → 눌리는가 (리사이즈 띠가 버튼을 먹지 않는가)
4. 마우스업 뒤 `document.documentElement.className` → 잔류 커서 클래스가 없는가
5. `window.dispatchEvent(new Event('resize'))` → 화면 밖 모달이 들어오는가

⚠️ **시험 전에 `innerWidth` 와 `document.hidden` 을 먼저 확인할 것.**
브라우저 패널이 숨겨져 있으면 rAF 가 멈춰 "동작 안 함"으로 보이고, 패널이 좁으면
(실측 413px) 모달이 화면 경계에 붙어 `w = innerWidth - GAP - left` 로 고정돼
"폭이 안 변한다"는 **거짓 실패**가 난다. 둘 다 코드 문제로 오인하기 쉽다.
