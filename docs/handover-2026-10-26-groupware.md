## 3. 조사하는 방법 (이 세션에서 쓴 것)

조사 스크립트는 scratchpad 에 있었으므로 **세션과 함께 사라진다.** 다시 만들 때의 요점:

1. **`routes.json`** (`/resources/js/conf/routes.json`) — 조사 대상 화면 352개를 한 번에 파악.
2. **화면 열고 CDP Network 관찰** — `Network.enable` → `Page.navigate` → 이벤트 수집.
   가장 확실하지만 **세 모듈(주소록·알림·쪽지)은 진입만으론 호출이 0건**이었다.
3. **번들에서 `/api/` 문자열 긁기** — 모듈 화면을 **열고 난 뒤** `script[src]` 를 fetch 해서 정규식.
   호출 없이 그 모듈 경로 전체가 나온다. 이번 성과의 대부분이 이 방법이다.
   ⚠️ 번들 URL 엔 `?rev=` 가 붙는다 — 확장자 판정은 `split('?')[0]` 에만.
4. **파라미터 이름은 번들 코드의 `default` 객체에서** — 주소록이 그렇게 확정됐다
   (`contact/collections/search_contact`). 추측 금지.
5. 확정한 걸 `gw_bridge.py` 함수 → `kortek_backend.py` 라우트 → `QA_TOOLS` 한 줄로 이식.

### 검증 방법
- 라우트: `app.test_client()` — **사용자가 돌리는 5000번 프로세스를 죽이지 말 것.**
- 실제 HTTP 까지 보고 싶으면 **2차 인스턴스**를 띄운다. 모듈을 import 해서 `app.run(port=5001)` 만
  부르면 **예약 발송 스케줄러가 안 뜬다**(스케줄러는 `kortek_backend.py` 의 `__main__` 안에서만 기동).
  끝나면 명령줄로 PID 를 확인해 그것만 종료할 것.
- `/self-update` 는 **이 PC 에서 아무 일도 안 한다** — git 작업본이라 의도적으로 건너뛴다
  (`devMode: true`). 그 기능은 팀원 PC 용이다. 여기서 새 코드를 반영하는 방법은 **백엔드 재시작**뿐.
