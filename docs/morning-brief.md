## 2. 재료와 규칙 — js/59 와 같은 규칙

| 무엇 | 어디서 | 규칙 |
|---|---|---|
| 프로젝트 목록 | NAS `App_Config/project_index.json` | 명단에 있는 팀 · `completed` 제외 · 상한 `maxProjects` |
| 업무 | `<팀>/<파일>.json` 의 `globalData` | **리프 행만** · `_calcStartTs/_calcPlanTs`(없으면 날짜 칸) · 업무명은 `_orig*` |
| 내 업무인가 | `_담당구분` → 별칭(`BRIEF_DISC_ALIAS`) → 역할→`projectMeta.<역할>담당자`(`BRIEF_ROLE_FIELD`, 없으면 멤버-3) → 쉼표 다중 쪼개 **이름·계정id·별칭** 비교 | js/59 `isMine` 과 같은 사다리 |
| 지연 | 마감 < 오늘 && 상태 ≠ 완료 | |
| 이번 주 | 오늘 < 마감 ≤ 오늘+`weekAhead`(7) | |
| 어제 보고 | `DailyReport/<월>/<어제>__<key>.json` | 어제 = 마지막 근무일. 조회 실패면 그 줄을 **안 쓴다**(모름) |

⚠️ 두 표(`BRIEF_ROLE_FIELD`·`BRIEF_DISC_ALIAS`)는 js/15b `_MS_CATEGORY_FIELD_MAP`·js/04k
`_WBS_DISCIPLINE_ALIASES` 의 **사본**이다 — 앱 쪽에 역할이 늘면 여기도 한 줄 더한다. 하네스 7절 돌연변이가
빠진 역할을 잡아 준다.

## 3. 관문 (순서대로)

📣 담당 PC → `briefEnabled` → 근무일(`_nonworkdays.json`, 모르면 안 보냄) → `briefAt` 이후 → 사람마다 **하루 한 번**
(`briefLastFired`) → 사용 중 · 텔레그램 ID 있음 · `brief:false` 아님 · 휴가 아님.

미리보기(`/daily/tick` `{brief:true, force:true, briefOnly:<key>}`)는 관문을 건너뛰되 **그 사람에게만**.
`force` 없이 `briefOnly` 만 주면 자동 틱과 같은 관문을 탄다.
