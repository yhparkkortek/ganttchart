# Phase 11 — AI 문답 질문 라우터 + SAP 적립학습 (2026-09-21)

> 구현 완료(모킹/브라우저 검증). 실제 SAP 라이브 검증이 필요한 항목은 §8 참고.
> 관련: `docs/phase10-issue-learning-design.md`(이슈 수집 — 이 기능의 이벤트 수집·리포트 기반), `docs/ai-qa.md`, `docs/sap-lookup.md`.

## 1. 배경 — 왜 만들었나

질문이 **SAP 조회 / 프로젝트 JSON 분석 / 일반 추론 / 기타** 중 무엇인지 구분을 못 했다. 정규식 로컬 명령 약 10개가 먼저 걸러내고,
나머지는 프로젝트 JSON이 통째로 실린 하나의 큰 프롬프트로 가서 AI가 알아서 판단했다. 실제 사례: `SMAJ12A* 조회해줘`(자재내역 패턴 = SAP 조회)가
어떤 정규식에도 안 걸려 프로젝트 데이터 답변("데이터에서 확인되지 않습니다 → AI 추론(일반 지식)")으로 새어 SAP에 없는 정보를 지어낸 것처럼 답했다.

## 2. 라우터 (`js/33-qa-router.js`) — 규칙 우선, 확실할 때만 동작을 바꾼다

**원칙: 확실하지 않으면 기존(legacy) 경로를 그대로 쓴다** — 라우터가 틀려도 지금보다 나빠지지 않게.

| 단계 | 내용 | AI 호출 |
|---|---|---|
| 0 명시 지정 | "자주 쓰는 질문" 줄 오른쪽의 분류 선택 상자 `[자동·SAP·프로젝트·추론]`(세션 유지, 지정 중이면 파란 강조) 또는 접두어 `#sap ` `#프로젝트 ` `#추론 `(그 턴에만) | 없음 |
| 1 규칙 점수 | `_qaClassify(question)` — 순수 함수 | 없음 |
| 2 AI 분류 | **미구현(예정)** — 데이터가 쌓인 뒤 애매한 경우에만 200토큰짜리 JSON 분류 | 예정 |

**클래스**: `sap`(🏭) · `project`(📊) · `action`(⚙️ 앱 동작: 알람/공지/메일/수정 — 표시만, 동작은 legacy) · `general`(💡) · `other`(💬) · `auto`(불확실 → legacy).

**1단계 신호(점수)**
- SAP: `SAP` 단어 +5, tcode(`ZPP038`/`MM03`/`ME23N`… 대문자) +4, 와일드카드 패턴(`SMAJ12A*`) +4, 자재번호 5~8자리 +3(8자리 날짜·`#G` 인덱스 제외), 기능 카탈로그 키워드 최대 +4.
- 프로젝트: 업무/일정/담당(자)/지연/마감/프로젝트… 어휘(개당 +2, 최대 8) + **존재 확인**(질문 속 부품번호·모델명·한글 고유명이 실제 프로젝트 데이터에 있는가, +3/+2). `haystack()`이 `globalData`+`tabData`를 소문자로 30초 캐시.
- 일반: "뭐야/차이/왜/설명해" 표현 +2, SAP·프로젝트 신호가 전혀 없으면 +2 — **프로젝트·SAP 신호가 조금이라도 있으면 확정하지 않음**(오분류 시 프로젝트 질문이 데이터 없이 답해지는 걸 방지).
- 확정 조건: 1등 ≥ 4점 **그리고** 2등과 격차 ≥ 3점. 아니면 `auto`.

**클래스별 동작 (확정됐거나 사람이 지정한 경우)**
| 클래스 | 동작 |
|---|---|
| sap + 와일드카드 패턴 | **새 로컬 명령**: `/sap-material-pattern` → 자재번호+자재내역 목록(최대 150줄 표시). 브릿지 `resolve_pattern` = 기존에 실사용 검증된 `resolve_materials_by_description_pattern`(MM60 F4, 읽기만) 재사용 |
| sap + 자재번호/(tcode·SAP + "화면") | `route.useSapContext` → 04h의 기존 SAP 게이트가 열려 `_aiFetchSapContext`(BOM/사용처/ZMM009/현재 화면) 사용 |
| sap + 그 외 | **미지원 안내**(§4) — 프로젝트 데이터로 지어내지 않음 |
| general | 프로젝트 JSON 미포함 **가벼운 프롬프트**(`_qaBuildGeneralPrompt`) — 빠르고 싸며 "데이터에 없다더니 추론" 오답 방지 |
| project / action / other / auto | 기존 경로 그대로 |

**🎨 분류별 색(2026-09-21, 사용자 지시)**: 자동=파랑(기존 색 그대로) · 프로젝트=초록 · 추론=살구 · SAP=빨강 — 기본 파스텔 R·G·B + 살구. 분류 선택 상자(옵션 목록 포함)와 **내 질문·답변 말풍선**(질문은 진한 파스텔, 답변은 더 연하게 + 테두리)에 적용. 색은 코드가 아니라 **`window._qaClassPalette` 표(데이터)**에 있으니 바꾸려면 그 표만 고친다(글자 대비 4.5:1 이상 유지 — 드래그 선택 하이라이트가 안 보이던 2026-08-29 문제 참고). 말풍선 색은 메시지의 `route.cls`로 정해지고(사용자 메시지에도 route를 붙임), route가 없는 옛 메시지·오류·auto/action/other는 기존 파랑/회색/빨강 그대로.

**보이는 분류 + 다시 분류(한 줄 푸터)**: 답변 아래 한 줄 — 왼쪽 `🏭 SAP 조회 ⇄`(툴팁에 판단 근거), 오른쪽 `도움이 되었나요? 👍 👎 🚩`. `⇄`를 누르면 `다시 분류: [📊프로젝트로][💡추론로]`가 펼쳐지고(기본은 접힘 — 화면 정리), 클릭하면 `#접두어 + 원래 질문`으로 재실행하며 `reroute` 이벤트를 남긴다 — **사람이 교정한 정답 데이터**라 리포트에서 규칙 보강 후보가 된다.

## 3. 훅 위치 (거대 파일엔 최소한만)

`js/04h-core-app-upload-utils-3.js`의 `sendGanttQaMessage`: **H1** 맨 앞 접두어 파싱(`_qaParsePrefix`), **H2** 로컬 명령들 이후·`apiKey` 확인 직전 `_qaRouteAndMaybeHandle`(handled면 return), **H3** SAP 게이트에 `_qaRoute.useSapContext` OR(단, 사람이 프로젝트/추론으로 **직접 지정**했으면 "SAP" 단어가 있어도 현재 SAP 화면을 읽지 않음),
**H4** general이면 `_qaBuildGeneralPrompt` 사용, **H5** AI 답변 메시지에 `route` 부착. `js/04g`: 답변 푸터 한 줄에 `_qaRouteInlineHtml(m)`(왼쪽 분류·⇄) + `_qaRerouteRowHtml(m)`(펼침 행). 분류 선택 상자는 `openGanttQaModal`을 래핑해 `ensureChips()`가 "자주 쓰는 질문" 줄에 삽입(모달 템플릿은 안 건드림).
**새 분류 규칙은 `_qaClassify` 한 곳에만** 넣을 것(테스트가 그 함수를 직접 부른다).

## 4. 미지원 SAP 요청 = 정직하게 안내 + 적립

지원하지 않는 SAP 요청은 프로젝트 JSON으로 추측 답변을 만들지 않는다. 안내문: 이해한 근거, 가장 비슷한 기능(유사도 %), 지금 가능한 SAP 요청 목록(카탈로그), "새 SAP 기능 후보로 적립했습니다". AI 호출이 없어 API 키·지연과 무관하다.

## 5. SAP 기능 카탈로그 (`js/32-sap-capabilities.js`) — 단일 원본

`window.SAP_CAPABILITIES`(id/title/tcode/mode/verified/kw/needs/ex). 쓰임: ① 라우터 어휘 ② 미지원 안내의 지원 목록 ③ 학습 적립의 "기존 기능과 얼마나 비슷한가" 비교 대상.
**새 SAP 기능을 구현하면 반드시 여기에 항목을 추가**한다(→ 이후 비슷한 요청이 "구현됨 이후 재요청"으로 추적됨). **kw에는 그 기능만의 구체적 단어만**(조회/자재/문서 같은 일반어는 프로젝트 질문과 섞여 오분류를 만든다).
`_qaMatchCapabilities(text)`(0~1 유사도), `_qaIntentSig(text)`(부품번호→`〈코드〉`, 패턴→`〈패턴〉`로 바꿔 "같은 종류의 요청"끼리 묶는 시그니처).

## 6. 적립학습 — 신고 버튼과 합친 학습 루프

**이벤트**(Phase 10 수집기로 Drive 샤드에 쌓임, 학습 이벤트는 `params.sig`+`params.caps` 포함): `sap_unsupported`(미지원 자동 적립) · `sap_feature_request`(🚩 "SAP에서 이것도 해줬으면") · `route_wrong`(🚩 "질문을 잘못 이해함") · `reroute`(다시 분류 클릭).
**🚩 신고 모달**에 분류 선택(답이 이상함 / 질문을 잘못 이해함 / 🏭 새 SAP 기능 요청)과 "어느 화면(tcode)에서 어떻게 하시는지" 메모.
**리포트 "🧠 SAP 학습 적립" 탭**(관리자): 같은 sig끼리 묶어 수요순(`사용자 수 × (건수 + 새 기능 요청×2)`)으로 표시, 결정론적 판정:
`🔁 기존 기능의 변형`(유사도 ≥ 0.6 — 트리거·라우팅 보강) · `🔀 유사`(≥ 0.3 — 확장) · `🆕 신규 후보`(< 0.3) · `🧭 라우팅 교정`.
**🤖 AI 추론**(버튼 눌렀을 때만 1회): 카탈로그 + 요청 샘플(마스킹됨)을 주고 `{kind, similarTo, tcodeCandidates, mode, neededFromUser, steps, risk, confidence, summary}` JSON을 받아 원장에 **적립**.
**원장**: Drive `Backups/SAP_Issues/sap_learning.json` — `{군집키: {status(new/reviewing/done/hold), hypothesis, at, by, doneAt}}`. 세션·사람이 바뀌어도 이어진다.
**digest**에 `learning` 배열 포함(상태·가설·샘플) → **"이슈 정리해줘"** 때 Claude가 수요순 신규 후보와 AI 가설을 함께 읽고 구현한다.
**구현 후**: 카탈로그에 항목 추가 → 리포트에서 `구현됨` → 이후 같은 sig 요청이 오면 `🔁 구현 후 재요청`(구현이 요청을 못 채웠다는 신호).

**운영 루프**: 사용자 사용 → (미지원 자동 적립 / 🚩 / 다시 분류) → Drive → 관리자가 리포트 확인·AI 추론·내보내기 → Claude가 digest를 읽고 구현(신규 기능: 필드 ID는 라이브 트리 덤프 1회 또는 사용자의 "기록 및 재생" 매크로로 확정) → 카탈로그+`구현됨`.

## 7. 개인정보·안전
질문은 마스킹한 앞 160자만(자재번호 등 5자리↑ 숫자·메일 마스킹), 답변 본문은 저장하지 않음. 수집은 본 기능을 방해하지 않음(try/catch). 라우터 예외는 무시하고 기존 경로로 진행. 수집 끄기: `localStorage.gantt_issue_collect_off='1'`.
