# 🛠 AI 문답 — 도구 자율 호출 (function-calling), 2026-10-19

## 왜 만들었나

그때까지 그룹웨어/SAP 조작은 `js/04h`에 **미리 박아둔 `if` 블록**이 했다. 카탈로그 어휘가
걸리면 정해진 라우트를 부르고, 안 걸리면 AI에게 텍스트로만 넘겼다. 그래서 구현해 두지 않은
조합("문서관리 승인 대기 보여줘")에는 AI가 "지원하지 않습니다"라고 답했다.
**AI가 거부한 게 아니라 부를 코드가 없었던 것이다.**

이 파일은 그 마지막 경로를 바꾼다 — 라우트 목록을 데이터로 들고 AI에게 보여주고, AI가
"어떤 도구를 어떤 인자로 부를지" 고르게 하고, 코드가 실행해 결과를 되먹인다.

| | 전 | 후 |
|---|---|---|
| 새 조회 기능 | 어휘 + if 블록을 매번 코딩 | `QA_TOOLS`에 **한 줄** 추가 |
| 못 하는 질문 | "지원하지 않습니다" | AI가 도구를 골라 조회 |
| 어휘 변형 | 카탈로그에 없으면 실패 | 뜻이 통하면 AI가 매칭 |

## 파일

| 파일 | 역할 |
|---|---|
| `js/40-qa-tool-router.js` | 도구 레지스트리(`QA_TOOLS`) + 인자 검증 + 실행 + 에이전트 루프 |
| `js/04h` (`_qaToolLoop` 호출부) | 일반 AI 호출 **직전**에 끼워 넣은 폴백 |
| `kortek_backend.py` `/gw/*` | 도구가 부르는 읽기 라우트 |
| `gw_bridge.py` | 그룹웨어 내부 API 호출 |

## 동작 순서

```
질문
 ├─ ① 기존 결정론 블록 (어휘 매칭 if)        ← 여전히 **최우선**. 바뀐 게 없다
 ├─ ② SAP 의도 감지 → _aiFetchSapContext     ← 루프가 가로채지 않는다
 ├─ ③ 🆕 도구 루프 (_qaToolLoop)
 │     1. AI에게 도구 목록 + 오늘 날짜 + 질문을 주고 호출을 고르게 한다
 │        → `[[TOOL:gw_mail {"from":"2026-10-19","to":"2026-10-19"}]]`
 │        → 도구가 필요 없으면 `[[NO_TOOL]]` → null 반환 → ④로
 │     2. requires:'gw'면 /gw/status로 로그인 확인 (실패 시 호출 자체를 안 한다)
 │     3. 스키마로 인자 검증·보정 → 실행 (최대 4회)
 │     4. 결과를 AI에게 되먹여 요약. **AI가 실패해도 원자료는 보여준다**
 └─ ④ 기존 일반 AI 경로 (프로젝트 컨텍스트 프롬프트)
```

## ⚠️ 안전 설계 — 왜 이렇게 했나

1. **읽기만.** `mode:'read'`가 아닌 도구는 `_qaRunTool`이 거부한다. 쓰기(기안 임시저장 등)는
   사람 확인 경로를 그대로 쓴다 — AI가 스스로 쓰지 않는다(CLAUDE.md).
   `gw_approval_draft`(쓰기)를 id로 넣어 봐도 레지스트리에 없어 거부된다.
2. **AI는 도구 id만 고른다.** 엔드포인트 문자열을 AI가 정하지 못한다. URL은 레지스트리의
   `path`로만 조립하고 `BACKEND`(127.0.0.1:5000) 아래로 고정한다.
3. **인자는 전부 검증·보정한다.** 실측 확인:
   | AI가 준 값 | 결과 |
   |---|---|
   | `limit: 99999` | 80으로 깎음(상한) |
   | `limit: -5` | 1로 올림 |
   | `path`, `endpoint` 같은 스키마 외 인자 | **버림** + 사유 기록 |
   | `folder: '../../etc/passwd'` | 허용값 아님 → **기본값으로** 떨어뜨림 |
   | `from: '어제'` | 날짜 형식 아님 → 기본값 |
   | `keyword` 500자 | 40자로 자름 |
   | 필수 인자 누락 | 호출 안 함 + 사유 반환 |
   ⚠️ **규격 위반은 "인자를 빼는" 게 아니라 "기본값으로 떨어뜨린다"** — 빼면 서버 기본값이
   적용돼 *사용자가 말한 것과 다른 조회*가 조용히 일어난다.
4. **호출 횟수 상한** — 한 턴에 도구 3개, 총 4회.
5. **투명** — 무엇을 어떤 인자로 불렀고 몇 건 왔는지 답변 끝에 그대로 붙인다
   (`_qaToolCallsFooter`). 블랙박스로 두지 않는다.
6. **신호 기록** — 모든 호출을 `localStorage.gantt_qa_tool_log_v1`(최근 300건)에 남기고,
   실패는 `_issueLog`(Phase 10)로도 보낸다. `STORAGE_REGISTRY`에 정리 규칙 등록됨.

## ⚠️ kw 만으로 결정론 실행하지 말 것 — `strongKw` (2026-10-22)

`GW_CAPABILITIES` 의 `gw_approval_draft` 는 양식이 **`원자재 승인 결과서` 하나로 고정**인데,
`kw` 에 `기안 작성`·`기안해줘`·`전자결재` 같은 **일반적인 말**이 들어 있었다.
매칭이 토큰 순서 + 간격 허용(`_qaKwSeqHit`)이라 "등록**기안** 하나 **작성**"도 `기안 작성`으로 걸린다.

결과: **"502573 제품코드 등록기안 하나 작성해줘" 가 승인원으로 실제 임시저장됐다**(문서 220176).
어제 붙인 `gw_approval_compose` 는 **차례가 오지도 않았다** — 결정론 블록이 먼저라서.

**규칙 셋:**

1. **그 기능을 특정하는 말을 `strongKw` 에 적고**(`_gwCapStrongHit`, js/32),
   그게 있을 때만 결정론으로 간다. 일반 `kw` 는 **카탈로그·학습용으로 남긴다**(지우지 말 것).
   `strongKw` 를 안 적은 기능은 기존대로 `kw` 판정 — 동작이 안 바뀐다.
2. **애매할 때 그냥 흘려보내면 안 된다.** 도구 루프는 `mode:'write'` 를 거부하므로
   **아무 일도 안 일어난 채** 끝나고, 사용자 눈엔 무시당한 것으로 보인다. **되묻고 선택지를 줄 것.**
3. **되묻기 버튼이 보내는 문장은 되묻기 블록보다 _위_ 에서 처리할 것.**
   아래 두면 그 버튼이 되묻기를 다시 띄워 **무한 반복**된다(그럴 뻔했다).

## 새 도구 추가하는 법

`QA_TOOLS`(js/40)에 한 항목 추가하면 끝이다. 프롬프트·검증·실행이 자동으로 따라온다.

```js
{ id: 'gw_xxx', mode: 'read', requires: 'gw',
  title: '화면에 보여줄 이름',
  desc: 'AI가 언제 이걸 골라야 하는지 — 여기에 적은 설명이 선택 정확도를 결정한다',
  path: '/gw/xxx', pick: 'rows',          // 응답에서 배열이 담긴 키
  params: [ { name:'from', type:'date', desc:'...' } ] }
```

`type`은 `date` / `int`(min,max) / `bool` / `enum`(enum) / `text`(max). `def`는 기본값,
`req: true`는 필수. **`desc`를 성의 있게 쓸 것** — AI가 도구를 고르는 유일한 근거다.

## ⚠️ 실측으로 배운 것 (도구 `desc`에 반영해 둠)

- **엉뚱한 필드로 검색하면 조용히 0건이 온다.** 사내 승인원 문서는 제목이 영문
  (`Customer Approval Sheet...`)이라 `searchtype=title&keyword=승인원`은 **0건**,
  `searchtype=formName&keyword=승인`은 18건이다. "0건 = 자료 없음"으로 단정하면 틀린다.
  → `gw_approval_box`의 `desc`에 "0건이면 다른 필드로 한 번 더" 지시를 넣어 뒀다.
- **설문 목록은 서버가 `offset`을 무시한다**(limit=3을 줘도 20건). `gw_bridge.surveys`가
  코드에서 자른다. 다른 모듈처럼 offset이 먹는다고 가정하지 말 것.
- **문서관리/설문의 "대기" 목록은 평소 0건이다.** 기능이 고장 난 것과 구분이 안 되므로
  0건일 때 "그 조건에 자료가 없다"를 명시적으로 AI에게 알려준다(`_qaToolResultsText`).

## 한계 (정직하게)

- **네이티브 function-calling이 아니다.** GAS 프록시를 거치므로 공급사 tool API를 못 쓴다.
  대신 앱에 이미 있는 `[[ACTION:...]]`과 같은 텍스트 프로토콜(`[[TOOL:id {json}]]`)을 쓴다.
  모델이 형식을 못 맞추면 도구 없이 기존 경로로 떨어진다(조용히 실패하지 않고 그냥 폴백).
- **AI 호출이 2번 늘어난다**(계획 + 요약). 결정론 블록이 걸리는 질문은 루프를 아예 안 타므로
  자주 쓰는 질문은 느려지지 않는다.
- **다단계 추론은 1턴만** — "게시판 id를 찾고 → 그 게시판을 조회"처럼 결과를 보고 다시
  고르는 건 지금 안 된다(계획 한 번 → 실행 → 요약). 필요하면 루프를 2턴으로 늘려야 한다.

## 쓰기 (js/41-qa-write-tools.js)

### 왜 읽기와 **다른 경로**인가
자율 루프(js/40)는 **읽기만** 실행한다. 쓰기를 같은 루프에 넣으면 AI가 한 번 잘못 고른
순간 되돌릴 수 없다(예약이 동료에게 보이고, 메일이 나가고, 결재가 상신된다).

```
AI/코드가 초안 → 확인 카드에 값 그대로 → 사람이 1회 확인 → 그 다음 끝까지 자동
```
앱의 기존 원칙과 같다 — 구매오더·자재 보관함이 "확인 1회 후 자동", 전자결재는
"임시저장까지만, 상신은 사람"(CLAUDE.md).

### 🔒 구조적 가드
1. `_qaRunTool`(읽기 루프)은 `mode:'write'`를 **영구 거부**한다.
2. 실행기 `_qaExecWriteDraft(nonce)`는 `_qaPendingWrite`의 **nonce**를 받아야만 돈다 —
   루프가 위조할 수 없고, 실행 직전에 초안을 비워 **재실행도 막는다**.
3. `confirmPhrase`가 있는 도구(발송·글등록)는 사용자가 그 단어를 **직접 입력**해야 한다.
4. `verified !== 'live'`면 실행 자체를 거부한다(아래).

### ⚠️ `verified` 필드가 핵심 — 추측으로 쓰기를 보내지 않기 위한 장치
| 값 | 뜻 |
|---|---|
| `live` | 실제 호출로 동작 확인됨 → 실행 가능 |
| `pending` | 경로는 알지만 **요청 본문 미확정** → 실행 차단, 사유만 안내 |

**`pending`은 AI 프롬프트에 아예 넣지 않는다**(`_qaWriteToolsSpec`이 걸러낸다) —
제안해도 막혀 있으면 "해준다더니 안 된다"는 경험만 남는다.

### 쓰기 표면을 왜 번들로 못 배웠나 (2026-10-19 실측)
읽기 경로는 번들에서 `/api/...` 문자열로 다 나왔다. 쓰기는 안 나온다:
- 공통 프레임워크 JS 59개에서 전자결재 쓰기 경로 7개는 뽑혔다
  (`PUT /api/approval/official/{approve,return,cancel,rerequest,addreceiver}`,
  `PUT /api/approval/manage/document`, `POST /api/approval/document/contentpreview/preview`)
- 그런데 **payload 필드 이름은 하나도 안 나온다** — 압축 코드가 변수로 조립한다.
- **예약·일정은 경로조차 안 나온다** — 모듈 코드가 그 59개 안에 없다.

→ 쓰기는 **사람이 1회 수행하는 동안 관찰**하는 것이 유일하게 확실한 방법이다.
   캡처 도구: scratchpad `gw_capture_write.py` (관찰만 — 클릭도 재전송도 하지 않는다).
   GET이 아닌 요청만 본문까지 기록한다.

```bash
python gw_capture_write.py write_capture.json 90
# → 90초 안에 그룹웨어에서 해당 작업을 한 번 직접 수행
```

### 막혀 있어도 쓸모 있게
"내일 회의실 예약해줘"는 거부로 끝내지 않는다 — `gw_asset_reservations`(읽기)로
**그날 실제 예약 현황을 조회해** 빈 시간을 보여주고, 무엇이 있으면 자동화되는지 밝힌다.
어휘 분리 확인: "회의실 예약해줘"=쓰기 / "예약 현황 보여줘"=읽기(도구 루프로).
