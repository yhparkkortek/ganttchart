# 📁 문서 저장소 — 사내 네트워크 공유(UNC)를 앱의 자료 보관처로

> **읽을 때**: 사양서·사진·메일 첨부를 어디에 두는가, `/doc/*` 엔드포인트, 패널 PN으로 사양서 찾기,
> 분류 확정 메일의 `.eml` 보관과 staging 정리.
>
> ⚠️ **이 저장소는 GitHub Pages로 공개돼 있다** — 사내 IP·공유 경로를 이 문서나 코드에 적지 말 것.
> 실제 경로는 각 PC의 `docstore_config.json`(.gitignore)에만 있다.

## 왜 Drive가 아니라 사내 공유인가 (2026-10-22)

"사양서 PDF·사진을 구글 드라이브에 쌓으면 용량이 걱정된다"에서 출발했다. 실측해보니

- 사내 공유에 패널 SPEC이 **이미 PN 파일명으로** 정리돼 있었다(197개, 평균 1.5MB)
- 거기 그대로 두면 **용량 문제가 애초에 없고 팀 공유도 이미 된다**

→ Drive로 복사할 이유가 없다. 남는 문제는 하나뿐: **브라우저는 UNC(`\\서버\공유`)를 직접 못 읽는다**
(Chrome이 차단). 그래서 **로컬 백엔드가 중계**한다 — `C:\SAP_DMS`에 쓰고 읽는 기존 패턴과 같다.

### AI는 원본을 보지 않는다 — 이게 설계를 정했다

`js/42`의 AI 매핑은 `_pxExtractText`로 **글자만 뽑아 6만 자로 잘라** 보낸다. 원본 바이너리는 AI에
간 적이 없다. 즉 **재분석·검색에 원본이 필요 없다.**

| | 크기 |
|---|---|
| 사양서 PDF | 2~30MB |
| 추출 텍스트(6만 자) | 30~80KB |

그래서 텍스트는 **항상** 캐시하고(`_text/`), 원본은 공유에 그대로 둔다.

## 폴더 구조

```
<공유>\개발자료실\
  PANEL\      패널 사양서 — ★ 파일명이 곧 패널 PN
  CUSTOMER\   고객 사양서
  PARTS\      PARTS 탭 자료 — 부품 구분별 하위 폴더
  MAIL\
    _staging\   수신 중 .eml (분류 대기)
    <프로젝트>\  분류 확정분
  _text\      추출 텍스트 캐시 (앱 생성)
  README.txt  탐색기로 들어온 사람에게 "손대면 안 되는 것"을 알림
```

- **폴더 목록은 설정이다**(`docstore_config.json`의 `folders`) — 사진 등 새 분류는 이름만 추가.
  코드를 안 고친다.
- `[BACK UP]` 아래에 두지 않는다 — **백업이 아니라 운영 데이터**다. "오래돼 보여서" 정리당한다.
- `README.txt`가 중요하다. 없으면 몇 달 뒤 누가 폴더를 정리하다 깨뜨린다.

| | |
|---|---|
| `GET/POST /doc/config` | 경로·폴더 목록 |
| `GET /doc/list` | 목록. `since=ISO`면 그 이후 추가분만(자동 등록 스캔용) |
| `GET /doc/get` | 원본 그대로 |
| `POST /doc/put` | 업로드. 같은 이름은 **409** (`overwrite=1`로만 덮어씀) |
| `GET/POST /doc/text` | 추출 텍스트 캐시 |
| `POST /doc/mail-assign` | staging → `MAIL/<프로젝트>/` |
| `POST /doc/mail-gc` | staging 정리 (기본 **dry-run**) |
| `GET /doc/mail-list` | 프로젝트별 보관 현황 |

### 지킬 것

- **경로 탈출 차단이 기본값.** 이 백엔드는 공유에 쓰기 권한이 있어서, 파일명을 그대로 믿으면
  공유 어디에나 쓸 수 있게 된다. `basename`만 취하고 `..` `/` `\` `:` 거부, 폴더는 화이트리스트.
- **텍스트 추출은 프런트가** 한다(pdf.js·XLSX가 이미 있음). 백엔드에 PDF 라이브러리를 깔면
  팀원 PC마다 설치 부담이 생긴다. 추출기는 `window._pxExtractText`(js/42) **하나만** 쓴다 —
  복제하면 "여기선 읽히는데 저기선 안 읽힌다"로 갈라진다.
- 실패를 빈 결과로 삼키지 않는다 — 백엔드 미기동과 경로 불가를 구분해 사유를 띄운다.

## 패널 PN → 사양서

파일명이 곧 PN이라 **색인이 필요 없다**(`_dsFindPanelSpec`). 표기 차이(점·하이픈·공백·대소문자)는
무시하고 맞춘다 — `G101EVN01.0` ↔ `G101EVN010`. **4글자 미만 PN은 거부**(아무거나 걸린다).

> ⚠️ 그래서 `PANEL\` 안 파일 이름을 바꾸면 앱이 못 찾는다. README에도 적어 뒀다.

## 메일 `.eml` 보관

지금 `extract_attachments()`는 **메타데이터만** 뽑고 내용은 버린다 — 첨부가 영영 사라진다.
`.eml` 한 파일에 본문+첨부가 다 들어가므로 통째로 두면 첨부를 따로 다룰 필요가 없다.

- 수신 중 `_staging`에 저장 → 프로젝트 확정 시 이동.
- **키는 `fileName`** — 프런트가 모든 경로에서 이미 들고 다니는 유일한 식별자다. 응답에 새 필드를
  끼워 넣으면 경유지마다 빠뜨리는 사고(`mailRaw` 패턴, `docs/mail-pipeline.md`)를 그대로 반복한다.
- 파일명은 `<fileName머리>__<sha8>.eml` — 같은 날·같은 제목이어도 내용이 다르면 구분된다.
- **수신을 절대 막지 않는다.** 저장 실패는 `_stage_raw_mail` 안에서 삼킨다. 자동수집이 하루 단위로
  같은 메일을 다시 받으므로 **이미 있는 파일은 건너뛴다**(같은 1MB를 10분마다 다시 쓰지 않도록).
- 프런트 훅은 **`_tpAppendMailSignal` 하나만 감싼다**(js/48). 그 함수는 "프로젝트로 확정됐다"는
  순간에만 불리고 새 배치 경로도 관례상 같이 부른다. 배치 코드마다 훅을 심으면 하나씩 빠뜨린다.

### staging 정리(GC)는 기간이 아니라 **큐 연동**

실측에서 신규발신자 큐에 **한 달 넘게** 남은 메일이 있었고, "프로젝트를 나중에 만들고 과거 메일을
재분류"가 이 앱의 정상 워크플로다(2026-10-22에 실제로 그렇게 했다). 그래서 기간만으로 지우면 틀린다.

- 프런트가 `alive`(미분류·보관함·신규발신자·폐기 큐에 살아 있는 `fileName`)를 보낸다.
- 거기 **없고** `DOCSTORE_GC_DAYS`(60) 지난 것만 대상. 기간은 **최후 방어선**일 뿐이다.
- 용량 상한 `DOCSTORE_GC_MAX_GB`(20) 초과분은 오래된 것부터 추가.
- 기본 **dry-run** — 실제 용량을 보고 숫자를 조정한 뒤에 켠다(측정 먼저).

### 🗂 하위 폴더 — `PARTS/<부품 구분>` (2026-10-22)

PARTS 탭은 주요자재 구분마다 자료를 갈라 둔다. 그래서 `folder` 가 **한 단계 하위까지** 받는다:
`PARTS/PANEL`, `PARTS/CONV`, `PARTS/SLIM CUT` …. 상위(`PARTS`)는 화이트리스트에 있어야 한다
(설정 `docstore_config.json` + `DOCSTORE_APP_FOLDERS`), 하위 이름은 파일명과 같은 규칙(`_docstore_safe_name`)으로 걸러진다.

- **두 단계 이상은 거부**(`PARTS/A/B`)·**상위 참조도 거부**(`PARTS/../CUSTOMER`) — 깊이를 열어 둘
  이유가 없고, 이 백엔드는 공유에 **쓰기 권한**이 있어서 경로 탈출이 곧 사고다. `_docstore_folder_segs`.
- 없는 하위 폴더는 **첫 조회에서 만든다** — 13개 구분 폴더를 따로 만들어 둘 필요가 없다.
- ⚠️ **PANEL만 `PARTS/` 아래가 아니다** — 회사가 이미 루트 `PANEL\` 에 데이터시트 ~200개와
  비교표 엑셀을 쌓아 뒀고 `_dsFindPanelSpec`(js/48)도 그 폴더를 본다. 카탈로그의 `nasFull: 'PANEL'`.
  빈 `PARTS/PANEL` 을 따로 뒀더니 **고르기 창에 그 빈 폴더만 떠서 비교표 엑셀을 고를 수가 없었다**
  (2026-10-22, 사용자 지적). 화면에서 닿지 않는 폴더는 없는 것과 같다.
- **폴더 이름은 `js/23` 의 `ELEC_CATEGORY_META[].nas`(데이터)가 정한다.** 구분명을 그대로 쓰지
  않는 이유는 `SLIM/CUT`·`TOUCH / GLASS` 처럼 Windows 폴더명에 못 쓰는 글자가 있기 때문이다.
  적어 두지 않은 구분(사람이 주요자재에 직접 넣은 것)은 그 글자를 공백으로 바꿔 쓴다.
- ⚠️ **텍스트 캐시 파일명은 `_doc_text_key()` 로 눕힌다**(`PARTS/PANEL` → `PARTS_PANEL`). 안 그러면
  `_text/PARTS/PANEL__x.pdf.txt` 로 가서 캐시가 **조용히** 안 먹는다(없는 폴더라 읽기도 쓰기도 실패).
  `/doc/list` 의 `hasText` 도 같은 키를 쓴다 — 한쪽만 고치면 "캐시 있는데 없다고 나온다".
- **앱이 쓰는 폴더는 설정에 없어도 허용·노출한다**(`DOCSTORE_APP_FOLDERS`). 폴더 목록은 **PC마다**
  각자 저장되므로(`.gitignore`), 앱이 폴더를 새로 쓰거나 이름을 바꾸면 팀원 PC에서만 "허용되지 않은
  폴더"가 난다 — `ELEC`→`PARTS` 가 그 경우였다. 화이트리스트의 목적은 **경로 탈출 차단**이고,
  앱이 정한 이름은 root 아래라 그 목적과 무관하다. `/doc/config` 응답에도 섞어서 돌려준다.
- 고르기 창(`_dsOpenPicker`)은 부르는 쪽이 **탭 목록을 줄 수 있다**(`opts.folders`, 문자열 또는
  `{f,label}`). 하위 폴더 이름은 설정에 없으므로 `cfg.folders` 만 보면 탭이 안 뜬다.
  페이지별 기본 폴더(`PAGE_EXCEL_SPECS.nasFolder`)는 **함수**도 된다 — PARTS는 화면 상태(지금
  고른 구분)에 따라 폴더가 달라진다.

### 🤖 NAS 파일 → AI 분석 → 표 저장

PARTS는 js/42의 공용 `ai` 블록(평평한 행 표)을 **쓰지 않는다** — 부품 종류마다 스펙 항목이 달라서
모양이 안 맞는다. 대신 이미 있는 "항목 추가 ▸ AI로 추출"(js/22d PANEL · js/22e 나머지)에 파일만
꽂아 준다(`_pcpAiFromFile` / `_pcpPickNasForAi`, js/50). 추출기·프롬프트를 복제하지 않는 이유는
**두 벌이 되면 한쪽만 고쳐지기** 때문이고, 그 흐름엔 사람이 결과를 보고 저장하는 단계가 이미 있다.

- 진입은 두 곳: 추가 모달의 `📁 NAS에서` 버튼, 그리고 📁 NAS로 **규격 엑셀이 아닌 파일**을 고른 경우
  (js/42 `spec.onForeignFile` → 처리했으면 공용 AI 경로로 안 넘어간다).
- 도표가 없는 구분은 AI 추출 대상이 없다 — 조용히 넘기지 말고 그렇다고 말한다.

### 📚 패널 비교표 엑셀 → 패널 라이브러리 일괄 이식 (2026-10-22)

회사 `Panel Comparison Table_*.xlsm` 의 **`REFERENCE` 시트**가 이 앱 패널 비교표와 같은 꼴이다
(0행=모델명, A열=항목 라벨, B열=우선순위 1/2, 섹션은 `[...]`). 실측: **패널 146개 · 쓰는 항목 109종 ·
칸 9,981개**(패널당 평균 68칸). 그래서 **AI를 안 쓴다** — 결정론 우선 + 무료 키 하루 한도.

- 구현: `js/51-panel-lib-import.js`. 진입은 ① 📁 NAS / 📂 불러오기로 그 파일을 고름
  (js/42 `spec.elecparts.blocks[0].preParse` — **AI 경로보다 먼저**) ② PANEL 추가 모달의 `📁 NAS에서`.
- 라벨은 **공백·대소문자·끝의 `:`를 무시**해서 맞춘다. 진짜 다른 것만 `PLI_LABEL_ALIASES`(데이터) —
  현재 한 줄뿐(`Late Time Order` → `Last Time Order`, 파일 쪽 오타). 안 맞는 12개는 전부 섹션 머리글이다.
- **읽기 1회 + 쓰기 1회.** `upsertPanelLibraryEntry`를 146번 부르면 Drive 왕복이 292번이다.
- **항목 단위 병합** — 파일 값이 이기고, 파일에 **없는 키는 그대로 둔다**. `Item Code`·`Part Name`·
  `Revision`·`T-CON`·`Rec.2020 Coverage`·`Voltage for Display Signals` 는 이 파일에 없으니,
  누가 손으로 채워 뒀으면 지우면 안 된다. 모델명 기준 **멱등** — 같은 파일을 두 번 넣어도 안 늘어난다.
- 값이 `-` 인 칸은 저장하지 않는다("해당 없음" 표시이고, 비교표 기본 표시가 이미 `-`다).
- 모델명의 `●` 머리표와 끝의 `[LNO-]` 꼬리표는 떼어낸다 — `PROJECT`·`PANEL COMP TABLE` 시트엔 붙어 있다.
  시트는 `REFERENCE` 우선(전체 목록), 없으면 머리행 꼴이 맞는 첫 시트.
- **사람 승인창은 없다**(사용자 요청: "이미 검증된 파일"). 대신 멱등 + 병합 + 결과 집계 토스트로
  되돌릴 일이 없게 했고, 못 읽은 라벨·건너뛴 열은 콘솔에 **드러낸다**(조용히 빠지면 "왜 이 칸만 비지"가 된다).
- ⚠️ `.xlsm` 이 `_pxIsWorkbook`/`PX_OK_RE`(js/42)에 빠져 있었다 — 그동안 이 파일이 "엑셀이 아닌 파일"로
  분류돼 AI 경로로 샜고, 거기서 이진 파일을 `file.text()`로 읽어 **깨진 글자를 AI에 보낼** 상태였다.
  `js/50` 의 AI 경로에도 엑셀 확장자 가드를 넣었다.

### 이 영역을 고칠 때 주의

- `days=0`을 "지금 다 비우기"로 기대하지 말 것 — **NAS 시계가 PC보다 약 1초 앞서서**
  방금 쓴 파일의 mtime이 미래로 찍힌다(실측). 60일 정책에는 영향이 없다.
- 설정값을 `or`로 읽지 말 것 — `days=0`이 falsy라 조용히 기본값으로 둔갑한다(테스트가 잡았다).
- 경로를 바꾸려면 **`docstore_config.json` 한 줄**이면 된다(코드에 없다). 단 **팀원마다 각자
  설정**이므로, 공유 폴더 이름을 바꾸면 각 PC에서 다시 설정해야 한다.
