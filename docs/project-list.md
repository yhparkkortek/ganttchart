# 📒 Project list — 제품(모델) 전수 목록 페이지

> 2026-10-29 신규. 구현은 `js/55-project-list.js` 한 파일 + HTML 탭 + styles.css 몇 줄.
> CLAUDE.md 는 색인만 두고 상세는 여기에 적는다.

## 무엇인가

고객사/공장/프로젝트별 **제품 한 줄씩**, 사양·담당자·패널·인증·판매량까지 91개 칸을 한 표에
모아 보는 전사 목록이다. 사내 엑셀 "제품 SPEC" 시트(실측 164행 × 92열)를 그대로 받는다.

Summary/Gantt 가 "프로젝트 하나"를 다루는 것과 달리 이 표는 **프로젝트를 가로질러** 존재한다.
그래서 저장도 프로젝트 JSON 이 아니라 **주소록과 같은 공용 파일**에 한다.

## ⚠️ 데이터는 저장소에 넣지 않는다

이 저장소는 GitHub Pages 로 공개돼 있다(CLAUDE.md). 고객사명·PN·패널 모델·판매량이 든 실제
표를 코드에 넣으면 사내 제품 정보가 그대로 공개된다. 그래서 **코드에는 빈 표 + 엑셀 불러오기만**
있고, 실제 데이터는 구글 드라이브(사내)와 각 PC 의 localStorage 에만 있다.

## 저장 구조

| 무엇 | 어디 |
|---|---|
| 행 + 변경 이력 | Drive `App_Config/ProjectList_Shared.json` (`{rows, history, savedAt}`) |
| 로컬 캐시 | `localStorage.gantt_project_list_shared` |
| 보기 상태(열 그룹·검색·필터·정렬·고정·숨긴 열) | `localStorage.gantt_pl_view_v1` — 사람마다 다르므로 Drive 에 안 올린다 |
| 제품별 문서 | NAS `PROJECTLIST/` 폴더, 파일명 `<KTK PN>__<원래이름>` |

**주소록(js/22f)의 안전장치를 그대로 가져왔다** — 둘 다 "여러 사람이 같은 공용 파일을 고치는"
구조라 같은 사고가 난다:
1. **빈 목록 덮어쓰기 차단** — 서버에 5건 넘게 있었는데 지금 올리려는 게 0건이면 동기화를 건너뛴다.
2. **낙관적 동시성 제어(`savedAt`)** — 쓰기 직전 Drive 의 `savedAt` 을 다시 읽어, 내가 마지막으로
   본 값과 다르면(= 다른 팀원이 먼저 저장) 덮어쓰지 않고 최신본을 다시 불러온 뒤 알린다.

## 열은 전부 데이터다

`PL_COLUMNS`(js/55) 한 곳에 `{k, ko, en, g, w, type}` 로 있다. 새 열은 **여기 한 줄**이면
표·상세보기·엑셀 입출력·필터·AI 도구가 전부 따라온다.

- `g` = 열 그룹(basic/owner/panel/optic/power/parts/cable/touch/mech/cert/sales).
  91열을 한 번에 보면 아무것도 안 보이므로 **그룹 칩으로 켜고 끈다**(기본: 기본·담당·패널).
- `type` = 특수 동작 — `person`(주소록 자동완성) · `panel`(패널 참조) · `doc`(NAS 문서함) ·
  `sap`(SAP 조회) · `part:<종류>`(PARTS 라이브러리) · `num`(오른쪽 정렬) · `sel`(필터 드롭다운).
- `PL_SHORT` = 머리글 줄임말(데이터). 머리글은 **한 줄 고정**이고 원래 이름은 말풍선(title)에 있다.
- `PL_HEADER_ALIASES` = 엑셀 머리글 별칭. 불러오기는 한/영/별칭 다 받고, 내보내기는 현재 언어 하나.

## 양방향 참조

| 열 | 누르면 | 반대 방향 |
|---|---|---|
| 담당자 4열 | 👤 주소록 카드(부서·직함·메일) | "이 담당자 제품 N건 보기"로 표를 거른다 |
| Panel | 🔎 앱 패널 라이브러리 전체 항목 + NAS 사양서 열기 | "이 패널 쓰는 제품 N건 보기" · PARTS 탭으로 |
| AD BD / CTRL | 🔎 PARTS 라이브러리 항목 | "같은 값 제품 N건 보기" |
| KTK PN | 🏭 SAP 자재내역/재고/가격/BOM | 같은 모델의 Gantt 프로젝트 찾기 |
| PN | 📎 NAS 문서함 + 🤖 AI 문서 분석 | 분석 결과가 Agile REV·생산REV 등을 채운다 |

SAP 조회는 **AI 문답 창에 질문을 넣어 보내는 방식**이다(`plAskAi`). 새 엔드포인트를 만들지 않고
기존 SAP 경로의 로그인·가드·결과 서식을 전부 그대로 쓰기 위해서다.

## 🤖 AI 문서 분석

NAS 문서의 글자를 뽑아(`_dsTextOf` → 실패 시 `_pxExtractText`) AI 에게 "이 행에 넣을 값"을 묻는다.

- 채우는 칸은 `PL_DOC_AI_FIELDS`(데이터) — 기본 agileRev/prodRev/pn/desc2/desc3/panel/panelMfr.
- **사람 승인 후에만 적용한다** — 항목별 체크박스가 있는 미리보기를 먼저 띄운다(CLAUDE.md
  "사람 승인 후 적용" 원칙). 적용된 값은 변경 이력에 before→after 로 남는다.
- 실패는 `_issueLog('project-list-doc-ai', …)` 로 신고한다(조용히 삼키지 않는다).

## 변경 이력

셀 하나 고칠 때마다 `{at, by, pn, desc, f(칸), b(전), a(후)}` 를 쌓고 Drive 에 같이 저장한다.
최근 3,000건만 남긴다. 엑셀 불러오기도 "교체/합치기" 한 줄을 남기고, 합치기 모드에서는 **바뀐
칸마다** 이력을 남긴다.

## 엑셀 입출력

- **불러오기**: 시트를 전부 훑어 **머리글이 가장 많이 맞는 시트/행**을 고른다(사내 파일에 의뢰서·
  계정대체 리스트 등 다른 시트가 같이 들어 있다). 그 다음 KTK PN 기준으로 **교체 / 합치기**를 묻는다.
- **내보내기**: 지금 보이는 열·행 그대로(그룹 칩과 필터가 그대로 반영된다).
- **NAS 보관**: 전체 91열을 엑셀로 만들어 `PROJECTLIST/ProjectList_YYYYMMDD.xlsx` 로 올린다.

## 알아둘 것(실측에서 물린 것)

- **머리글 정규화는 공백을 "지운다"** — 한 칸으로 줄이기만 하면 실제 파일의 `회로담당\n(PM)` 이
  `회로담당 (PM)` 이 되어 `회로담당(PM)` 과 안 맞는다. 이 열이 통째로 안 들어왔었다.
- **`table-layout:fixed` 는 표 자체의 폭이 정해져야 열 폭이 지켜진다.** 폭을 안 주면 브라우저가
  컨테이너 폭을 열 개수로 나눠 28열이 전부 35px 이 된다. 그래서 보이는 열 폭의 합을 표에 준다.
- **헤더 박스는 줄바꿈을 켜야 한다**(`#pl-header-box{flex-wrap:wrap}`). 검색+필터 6개+버튼 6개가
  한 줄에 안 들어가 오른쪽 버튼 묶음이 박스 밖(left:1272px, 박스 폭 1030px)으로 밀려나 통째로
  안 보였다.
- **셀은 누를 때만 입력칸으로 바꾼다.** 164행 × 91열을 전부 `<input>` 으로 그리면 1만 개가 넘는다
  (주소록은 8열이라 전부 input 으로 그려도 됐다).
