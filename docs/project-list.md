# 📒 Project list — 제품(모델) 전수 목록 페이지

> 2026-10-29 신규. 구현은 `js/55-project-list.js` 한 파일 + HTML 탭 + styles.css 몇 줄.
> CLAUDE.md 는 색인만 두고 상세는 여기에 적는다.

## 무엇인가

고객사/공장/프로젝트별 **제품 한 줄씩**, 사양·담당자·패널·인증·판매량까지 91개 칸을 한 표에
모아 보는 전사 목록이다. 사내 엑셀 "제품 SPEC" 시트(실측 164행 × 92열)를 그대로 받는다.

Summary/Gantt 가 "프로젝트 하나"를 다루는 것과 달리 이 표는 **프로젝트를 가로질러** 존재한다.
그래서 저장도 프로젝트 JSON 이 아니라 **주소록과 같은 공용 파일**에 한다.

## ⚠️ 데이터는 저장소에 넣지 않는다

이 저장소는 GitHub Pages 로 공개돼 있다(CLAUDE.md). 고객사명·PN·패널 모델·판매량이 든 실제
표를 코드에 넣으면 사내 제품 정보가 그대로 공개된다. 그래서 **코드에는 빈 표 + 엑셀 불러오기만**
있고, 실제 데이터는 구글 드라이브(사내)와 각 PC 의 localStorage 에만 있다.

## 저장 구조

| 무엇 | 어디 |
|---|---|
| 행 + 변경 이력 (**주**) | NAS `PROJECT LIST/ProjectList_<팀>.json` — 도면과 같은 자리, 구글 로그인 불필요 |
| 행 + 변경 이력 (보조) | Drive `App_Config/ProjectList_<팀>.json` — 구글 연동돼 있을 때만 같이 남김 |
| 로컬 캐시 | `localStorage.gantt_project_list_<팀>` |
| 지금 팀 | `localStorage.gantt_pl_team` (기본 `개발3팀`) — 머리글 바 드롭다운 |
| 보기 상태(열 그룹·검색·필터·정렬·고정·숨긴 열) | `localStorage.gantt_pl_view_v1` — 사람마다 다르므로 Drive 에 안 올린다 |
| 제품 도면/사양서 | NAS `PROJECT LIST/CUSTOMER` — **이름 그대로 두고 앞 숫자로 색인**(아래) |

**주소록(js/22f)의 안전장치를 그대로 가져왔다** — 둘 다 "여러 사람이 같은 공용 파일을 고치는"
구조라 같은 사고가 난다:
1. **빈 목록 덮어쓰기 차단** — 서버에 5건 넘게 있었는데 지금 올리려는 게 0건이면 동기화를 건너뛴다.
2. **낙관적 동시성 제어(`savedAt`)** — 쓰기 직전 Drive 의 `savedAt` 을 다시 읽어, 내가 마지막으로
   본 값과 다르면(= 다른 팀원이 먼저 저장) 덮어쓰지 않고 최신본을 다시 불러온 뒤 알린다.

## 저장은 언제 되나 (따로 "저장" 버튼이 없다)

칸을 고치면 **그 순간** 두 곳으로 간다.

| 시점 | 어디 | 의미 |
|---|---|---|
| 즉시(동기) | 이 PC `localStorage` | 창이 죽어도 **내 PC 에는** 남는다 |
| 3초 뒤(디바운스) | Drive 공용 파일 | 여기까지 와야 **팀원도 보는** 저장이다 |

디바운스를 두는 이유는 팀이 같이 쓰는 파일이라 타자마다 올릴 수 없어서다. 대신 **그 3초가 뜨기
전에 창을 닫으면 그 수정이 내 PC 에만 남는 구멍**이 있었다(2026-10-29 사용자 지적). 그래서 화면을
벗어나는 길목마다 `plFlushSave()` 로 디바운스를 건너뛰고 즉시 올린다:

- `visibilitychange`(hidden) — 탭 전환·최소화·닫기에서 가장 확실히 뜨는 신호
- `pagehide` / `beforeunload` — 보조
- 앱 안에서 **다른 탭으로 이동할 때**(js/23 `switchTab`)

머리글 오른쪽 표시가 상태를 그대로 보여준다 — 고치는 중엔 `● 저장 중…`(노랑), Drive 에 올라가면
`☁️ 드라이브 저장 <시각>`(초록). 노랑인 채로 오래 있으면 **드라이브 미연동**(비로그인)이라는 뜻이고,
그때는 localStorage 에만 쌓인다.

⚠️ **개별 프로젝트 JSON 과는 아무 상관이 없다.** 이 표는 프로젝트를 가로지르는 목록이라, 어떤
프로젝트를 열어 두었든 같은 팀 파일 하나를 읽고 쓴다(주소록과 같은 구조).

## 열은 전부 데이터다

`PL_COLUMNS`(js/55) 한 곳에 `{k, ko, en, g, w, type}` 로 있다. 새 열은 **여기 한 줄**이면
표·상세보기·엑셀 입출력·필터·AI 도구가 전부 따라온다.

- `g` = 열 그룹(basic/owner/panel/optic/power/parts/cable/touch/mech/cert/sales).
  91열을 한 번에 보면 아무것도 안 보이므로 **그룹 칩으로 켜고 끈다**(기본: 기본·담당·패널).
- `type` = 특수 동작 — `person`(주소록 자동완성) · `panel`(패널 참조) · `doc`(NAS 문서함) ·
  `sap`(SAP 조회) · `part:<종류>`(PARTS 라이브러리) · `num`(오른쪽 정렬) · `sel`(필터 드롭다운).
- `PL_SHORT` = 머리글 줄임말(데이터). 머리글은 **한 줄 고정**이고 원래 이름은 말풍선(title)에 있다.
- `PL_HEADER_ALIASES` = 엑셀 머리글 별칭. 불러오기는 한/영/별칭 다 받고, 내보내기는 현재 언어 하나.

## 📎 NAS 자료 연결 (PN 열) — 이름을 바꾸지 않고 **앞 숫자로 색인**

폴더는 `PROJECT LIST/CUSTOMER`(**띄어쓰기 포함, NAS 철자 그대로**). 실측 66개 파일이 전부
"7자리 고객 PN + 구분자 + (REV) + 리비전" 이름이었다:

```
1234567 REV K.pdf      1234567_REV J4.pdf     1234568_H.pdf
1234569-A.2 (1).pdf    1234570-revB (2).PDF   1234571 UPPER DISPLAY REV E.pdf
```
(⚠️ 번호는 **형태만 보이려고 지어낸 것**이다 — 실제 고객 PN 은 저장소에 적지 않는다.)

**색인 규칙**(`_plParseDocName`)
1. 파일명 **맨 앞 6~8자리 숫자** = 키.
2. 리비전은 `REV`(대소문자·`rev.`·붙여쓰기 전부) 뒤의 글자+숫자. `REV` 가 없으면 "구분자 + 리비전
   하나"로 본다(`_H`, `-B`, `-A.2`).
   ⚠️ **"숫자 바로 뒤 글자"로 잡으면 안 된다** — `1234571 UPPER DISPLAY REV E` 가 `U` 가 된다.
3. 끝의 `(1)` `(2)` 는 같은 리비전의 중복본이라 떼고 본다. `A.2`→`A2`, `J4`→`J4` 로 정규화.

**행 ↔ 파일 연결**(`_plRowDocNums`): 행의 `PN` 칸에 든 숫자 **전부**(한 칸에 여러 PN 이 줄바꿈으로
들어 있다) + `KTK PN`. 즉 **번호 길이로 가른다 — 7자리는 고객 PN, 6자리는 KTK 자재코드.** 폴더를
나누지 않아도 둘 다 같은 규칙으로 걸린다(사용자 질문 "6자리 숫자도 분류가 필요한데"에 대한 답).

**올릴 때도 이름을 헤집지 않는다** — 이미 그 행의 번호로 시작하면 그대로, 아니면 번호만 앞에
붙인다. 사람이 NAS 폴더를 직접 열어 쓰는 곳이라 앱이 `__` 같은 표식을 넣으면 안 된다.

**문서함 창**: 리비전별로 줄 세우고, 표의 `생산 REV`/`LNW Agile REV` 와 같은 리비전엔 ✅ 를 단다
(어느 도면이 "지금 것"인지가 제일 중요하다). 열기(새 탭) / 🖥️ 원본을 연결 프로그램으로 / 🤖 분석.

**드래그 앤 드롭**: 문서함 창의 점선 상자뿐 아니라 **표의 그 행 위에 바로 떨어뜨려도** 올라간다
(행이 초록 테두리로 표시된다).

⚠️ 백엔드 `DOCSTORE_APP_FOLDERS` 에 `'PROJECT LIST'` 가 있어야 하고 **백엔드 재시작이 필요**하다.
재시작 전에는 📎 개수가 안 보이고 문서함이 "허용되지 않은 폴더"로 뜬다.

## 알아둘 것(실측에서 물린 것)

- **머리글 정규화는 공백을 "지운다"** — 한 칸으로 줄이기만 하면 실제 파일의 `회로담당\n(PM)` 이
  `회로담당 (PM)` 이 되어 `회로담당(PM)` 과 안 맞는다. 이 열이 통째로 안 들어왔었다.
- **`table-layout:fixed` 는 표 자체의 폭이 정해져야 열 폭이 지켜진다.** 폭을 안 주면 브라우저가
  컨테이너 폭을 열 개수로 나눠 28열이 전부 35px 이 된다. 그래서 보이는 열 폭의 합을 표에 준다.
- **헤더 박스는 줄바꿈을 켜야 한다**(`#pl-header-box{flex-wrap:wrap}`). 검색+필터 6개+버튼 6개가
  한 줄에 안 들어가 오른쪽 버튼 묶음이 박스 밖(left:1272px, 박스 폭 1030px)으로 밀려나 통째로
  안 보였다.
- **셀은 누를 때만 입력칸으로 바꾼다.** 164행 × 91열을 전부 `<input>` 으로 그리면 1만 개가 넘는다
  (주소록은 8열이라 전부 input 으로 그려도 됐다).

## 행 메뉴 · 보기 편의

- **NO 숫자를 누르면 행 메뉴**가 그 자리에 뜬다 — ⌃⌄(위/아래로 이동) · ＋↑＋↓(위/아래에 행 추가) ·
  －(삭제) · 📌(맨 위 고정) · 📄 상세. 추가/삭제 뒤엔 번호를 다시 매긴다(`_plRenumber`).
  예전엔 NO 칸 안에 📌 아이콘이 같이 있어 **번호가 잘려 보이지 않았다**(44px 칸) — 고정은 메뉴로 옮겼다.
- **📌 고정**: 정렬·필터와 상관없이 그 행을 맨 위에 붙여 둔다. 지금 보고 있는 몇 건을 위에 두고
  나머지를 뒤지는 용도(사람마다 다른 상태라 Drive 가 아니라 `gantt_pl_view_v1` 에만 남는다).
- **제브라**: 행 배경을 JS 가 직접 준다 — sticky 칸(No·KTK PN)은 배경이 없으면 가로 스크롤 때
  밑줄이 비쳐 보이기 때문. 그래서 hover 는 CSS 에서 `!important` 로 덮는다.
- **긴 글 자르기**: `PL_CELL_MAX`(데이터) — 설명 1·2·3 은 20자까지만 보여주고 전문은 말풍선에.

## 속도

실측(164행 기준): 전체 91열 렌더 134ms, 3개 그룹만 42ms. 문제는 **검색창 타자마다 전체 재렌더**가
돌아 112ms 씩 먹던 것 — 글자를 칠 때마다 화면이 밀렸다. 그래서
1. 검색은 **160ms 디바운스**(입력이 멎은 뒤 한 번만),
2. 그때는 필터 드롭다운(값마다 건수를 다시 세고 `<select>` 를 새로 만든다)을 **건너뛴다**(`plRender(true)`).

열 그룹을 다 켜지 않는 것이 가장 큰 속도 요인이다 — 기본 3개 그룹이 그래서 기본값이다.

## 실사용에서 물린 것 (2026-10-29 2차)

- **드래그 앤 드롭이 "안 되던" 진짜 이유**: `js/04f` 가 **window 에** 드롭 핸들러를 걸어 두고
  "페이지 어디에 떨어뜨려도 간트 엑셀로 불러오기"를 한다. 내 핸들러에서 `preventDefault()` 만 하고
  전파를 안 끊으면 도면 PDF 가 그대로 그쪽으로 흘러가 엑셀 파서를 탄다. → `stopPropagation()` +
  `stopImmediatePropagation()` 필수. 그리고 **떨어뜨린 지점에서 행을 직접 찾는다**(dragover 가 한 번도
  안 뜬 채 drop 만 오는 경우가 있어, 기억해 둔 값에만 기대면 아무 일도 안 일어난다).
- **번호 정렬이 1, 10, 100 순**이던 것 — 글자 비교였다. `no` 는 항상 숫자로 보고, 그 외 열도
  **값이 전부 숫자면** 숫자로 정렬한다(KTK PN 등). 빈칸은 끝으로.
- **칸 오른쪽 아이콘은 `position:absolute` 로 고정**해야 한다. 값 뒤에 흘려 두면 PN 처럼 긴 값에
  밀려 **아이콘이 통째로 잘려 안 보인다**(사용자 지적). 값 쪽엔 `padding-right` 로 자리를 비운다.
- 팝업/행 메뉴 모양은 **파스텔 라운드 사각형**(파랑 이동 · 초록 추가 · 빨강 삭제)으로 통일한다.

## 읽기/쓰기 순서 (2026-10-29 사용자 제안)

**읽기: NAS → Drive → 이 PC 캐시**, 셋 다 비면 빈 표 + "엑셀 불러오기" 안내.
**쓰기: NAS 가 주**(3초 디바운스 + 이탈 시 즉시), 구글 연동이 있으면 Drive 에도 같은 내용을 남긴다.

NAS 를 주로 둔 이유: 도면이 이미 거기 있고, **구글 로그인 없이 팀 전체가 닿는다**. 엑셀은 "처음 한 번
넣는 수단"이고 평소 저장은 JSON 한 벌이라 가볍다.

동시 편집은 `savedAt` 으로 막는다 — 내가 마지막으로 본 시각과 지금 파일의 시각이 다르면 덮지 않고
최신본을 불러온 뒤 알린다(주소록과 같은 원칙).

⚠️ **NAS 루트 경로(UNC)는 코드·문서 어디에도 적지 않는다** — 저장소가 공개라서다. 경로는 각 PC 의
`docstore_config.json` 에만 있고, 코드는 폴더 이름(`PROJECT LIST`)만 안다.

## 팔레트

행 배경(제브라·고정행)·머리글 틴트·그룹 칩·NO 글자색은 **JS 가 인라인으로** 칠하므로, 팔레트가
주입하는 `<style id="cp-live-style">` 규칙이 못 이긴다. 그래서 `_pal()` 로 팔레트 색을 직접 읽어
쓰고, `_cpApplyLive()` 끝에서 `plRender()` 를 다시 불러 테마 전환을 따라가게 했다.

## 📁 NAS 버튼 — 다른 페이지와 같은 창을 쓴다 (2026-10-29)

버튼 이름은 다른 페이지와 똑같이 **`📁 NAS`**, 누르면 공용 창(`_dsOpenPicker`, js/48)이 그대로 열린다.
목록·열기·올리기·삭제·새 폴더·드래그앤드롭·연결 프로그램 열기·AI 여부 묻기까지 전부 공용 코드다
(이 페이지만 따로 만들면 생김새도 동작도 어긋난다 — js/42 `_dsImportToPage` 와 같은 자리).

탭은 두 개다: **📒 목록·백업**(`PROJECT LIST`) · **📐 고객 도면**(`PROJECT LIST/CUSTOMER`).

이 페이지가 더하는 것은 **고른 파일을 무엇으로 볼지**(`plNasPick`) 하나뿐:

| 고른 파일 | 하는 일 |
|---|---|
| `*.json` | 팀 목록 자체를 불러온다(확인 후 교체) — 되돌리기·다른 팀 파일 열람 |
| `*.xlsx/xls/csv` | 제품 목록 엑셀로 불러오기(기존 교체/합치기 흐름 그대로) |
| 그 밖(PDF 도면 등) | 공용 창과 같은 질문(AI/연결 프로그램) → AI면 **파일명 앞 숫자로 그 제품 행을 찾아** 분석에 건다 |

앞 숫자와 맞는 행이 없으면 분석하지 않고 "그 행의 PN을 먼저 채우라"고 알린다 — 엉뚱한 행에
값이 들어가는 것이 제일 위험해서다.

`plSaveToNas()`(표 전체를 엑셀 한 벌로 NAS 에 떨구기)는 함수로 남아 있지만 버튼에서는 뺐다 —
평소 저장은 NAS JSON 으로 자동이라 버튼이 "백업"을 뜻하는지 "저장"을 뜻하는지 헷갈렸다.

### ⚠️ 거의 전부 AI 없이 읽는다

`plExtractDwg(text)` 가 정규식으로 **30개 항목 전부**를 뽑는다(위 적중률이 그 결과다). AI 는
"🤖 AI로 더 읽기" 를 눌렀을 때만, 그것도 **정규식이 못 읽은 칸만** 물어본다 — 무료 키 하루 한도가
있고(CLAUDE.md), 규칙으로 되는 걸 AI 에 맡기면 환각이 섞인다.

**📐 도면 분석** 버튼은 도면이 연결된 모든 행을 한 번에 돌린다(AI 0회). 한 행에 도면이 여러 벌이면
**리비전이 가장 큰 것 하나만** 본다. 표에 사람이 적어 둔 값은 덮지 않고 **빈칸만** 채우며,
`dwg…` 전용 칸은 항상 최신 도면 값으로 갱신한다.

### 규칙을 짤 때 물린 것

- **PDF 글자는 CRLF 로 온다.** 줄 끝을 LF 로 보고 짠 규칙이 전부 빗나가 **도면 제목이 67개 중
  0건** 이었다. 맨 먼저 CRLF 를 LF 로 눕히고 시작한다.
- **설계 담당은 `ENGINEER` 라벨 옆에 없다.** 라벨 뒤엔 기밀 문구가 길게 붙고, 실제 값은 표제란
  순서(`제목 / 7자리 도면번호 / 담당 이니셜`)로 들어온다.
- **리비전을 "숫자 바로 뒤 글자"로 잡으면 안 된다** — 제목이 긴 도면에서 엉뚱한 글자를 집는다.
  `REV` 라는 말을 먼저 찾고, 없을 때만 "구분자 + 글자 하나"로 본다.
- **도면 제목은 표제란이 정답**이다. 느슨한 규칙은 주석 문장을 제목으로 집는다.

## 📐 도면 정보 모달 → 취사선택 등록 (2026-10-29 재설계)

처음엔 분석 결과를 **바로 표에 써 넣었는데**, 원하던 흐름이 아니었다(사용자 지적). 지금은
**표와 별개로 "그 도면에서 읽은 정보"를 정리한 모달을 먼저** 보여주고, 거기서 고른 것만 등록한다.

**모달이 보여주는 것** (`plShowDwgInfo`)
- 카탈로그 **30개 전부** — 못 읽은 항목도 회색으로 같이 보여준다(뭘 못 읽었는지도 정보다).
- 항목 / 도면에서 읽은 값 / 표의 값 세 칸. 표 값과 다르면 ⚠️ 로 나란히.
- 등록 가능한 항목에만 체크박스. 표와 이미 같으면 ✔ 만 보이고 체크박스가 없다.
- **기본 체크 = 읽혔고 표와 다른 것**. 단 ⚠️(표 값과 충돌)는 **기본 해제** — 사람이 판단할 일이다.
- 모달을 닫으면 표는 **그대로**다. [✅ 선택 항목 표에 등록]을 눌러야 들어간다(`plRegisterDwg`).

**📐 도면 분석(일괄)** 도 마찬가지로 바로 안 쓴다 — 행별로 "새 값 몇 개"를 목록으로 보여주고,
행을 골라 [선택한 행 등록] 하거나 [보기]로 그 행의 모달을 열어 항목별로 고른다.
엑셀에서 온 칸은 **빈칸일 때만** 채우고, 도면 전용 칸(`dwg…`)은 최신 도면 값으로 갱신한다.

## 📜 Agile REV 셀 → 도면의 REVISIONS 표 (2026-10-30 재설계)

**처음부터 원했던 기능은 이것이었다** — "Agile REV 열을 클릭하면 분석된 도면의 revisions 정보를
바로 보는 것"(사용자 정정). 앞선 구현들은 "값을 뽑아 표에 채우는" 쪽으로 가 있었다.

Agile REV 칸의 📜 를 누르면 그 행의 도면을 읽어 **도면 안의 표 두 개를 그대로** 보여 준다.

| 표 | 열 | 실측 적중 |
|---|---|---|
| REVISIONS | REV · 변경 내용 · 작성자 · 일자 | **66/66 파일**(표가 있는 전부), 433행 |
| DISPLAY INFORMATION MATRIX | 도면 머리글 그대로(REVISION·MFR PN·PART NUMBER·VENDOR·TOUCH CTRL·TOUCH SENSOR·TOUCH F/W·PANEL 등) | **15/15 파일**, 68행 |

- 표의 `생산 REV`/`Agile REV` 와 같은 리비전 줄은 **초록 배경 + ◀** 로 표시한다. 매트릭스는
  범위 칸(`G.5-J.4`)도 비교해서 그 안에 들면 맞춘 것으로 본다.
- 도면이 여러 벌이면 오른쪽 위 드롭다운으로 **리비전별로 갈아 가며** 볼 수 있다.
- 아래 [✅ 최신 REV(…)를 이 행에 넣기] 를 눌러야만 표가 바뀐다 — 보는 것과 쓰는 것을 분리했다.

### 파서가 상대하는 양식 차이(실측)

- **REVISIONS 머리글이 두 가지**: `REV. | DESCRIPTION | DRAWN BY | DATE` 와
  `REVISION | DESCRIPTION | BY/ DATE`(작성자와 날짜가 **한 칸**: `JG 06/06/22`).
- **날짜가 네 가지**: `6/15/2021` · `06/06/22` · `12-FEB-25` · `16 JAN 26`.
  → 이 셋을 다 받기 전에는 66개 중 9개가 0행으로 떨어졌다.
- **작성자 표기**: `A. SMITH` · `B.LEE` · `C.KIM` · `D,PARK`(**쉼표**도 쓴다).
- **매트릭스 열 구성이 양식마다 다르다**(8열/10열). 그래서 머리글을 이어 붙인 뒤
  `PL_MATRIX_COLS`(데이터) 사전으로 **긴 이름부터** 끊어 읽고, 본문은 **리비전 칸으로 시작한다**는
  규칙으로 행을 나눈다. ⚠️ 터치 F/W 로 행을 끊으면 그 칸이 `N/A` 인 옛 양식을 통째로 놓친다
  (15개 중 7개가 그랬다).
