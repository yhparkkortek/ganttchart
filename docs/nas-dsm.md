# 🗄️ NAS(Synology DSM) 연동 — 접속 권한을 사내 계정으로

앱 데이터를 구글 드라이브에서 NAS로 옮기는 길에서 **"로그인·권한"** 을 맡는 부분.
구글 로그인은 로그인이 아니라 **Drive 접근 토큰**이라, 그걸 떼면 데이터 접근이 같이 끊긴다 —
그래서 "로그인 방식 교체"는 사실상 **저장소 교체**와 한 몸이다.

⚠️ **사내 IP·공유 경로는 이 문서에도, 코드에도 쓰지 않는다**(저장소가 GitHub Pages로 공개).
   주소는 각 PC의 `nas_login_config.json`(.gitignore)에만 있다.

## 왜 SMB(`/doc/*`)가 아니라 DSM Web API인가

| | SMB/UNC 경유 (`/doc/*`) | DSM Web API (`nas_dsm.py`) |
|---|---|---|
| 권한 주체 | **Windows 로그인 사용자** (앱이 아님) | **DSM 계정** — 앱이 로그인한 그 사람 |
| 모바일·사외 | 불가(로컬 백엔드 필요) | 가능(HTTP API) |
| 실측 속도(호출 1회 고정비) | 44.2ms | **61.1ms** (연결 재사용 시) |

SMB 쪽 44.2ms는 **선이 느린 게 아니라 SMB 왕복이 잦아서**다(NAS까지 RTT <1ms, 3홉).
즉 VPN·사외에서 SMB는 훨씬 더 나빠진다 — API 쪽을 고른 이유.

## 실측으로 확정한 것 (2026-11-03)

- `SYNO.API.Auth` **maxVersion 7** · `SYNO.FileStation.List` maxVersion 2 — 둘 다 `entry.cgi`
- 비로그인 호출은 `{"error":{"code":119},"success":false}`
- **브라우저 쿠키 세션만으로는 API가 안 된다**(119). SynoToken도 노출되지 않고 SSO Server 패키지도 없다
  → 그래서 **백엔드가 로그인해서 `sid`를 들고 있는다**
- DSM은 **CORS 헤더를 주지 않는다** → 나중에 앱을 NAS에서 서빙해야 브라우저가 직접 부를 수 있다

## ⚠️⚠️ `session` 이름을 임의로 정하지 말 것 — 402의 진짜 원인이었다 (2026-11-03)

로그인에 쓰는 조합은 **실측으로 확정한 것**이다. 추측으로 바꾸지 말 것:

```
auth.cgi · version 3 · session=FileStation   ← 한 번에 성공
```

DSM은 `session` 값으로 **"어느 응용 프로그램에 로그인하는가"** 를 판정하고 그 응용 프로그램에
대한 계정 권한을 본다. 처음에 임의로 `session=KortekGantt`(앱 이름)를 넣었더니 **402(계정 권한
없음)** 가 났다. `entry.cgi` + v7/v6/v3 **전부 402** 였는데, 원인은 버전이 아니라 session 이름이었다.

**이 오진의 대가**: 402를 "NAS 쪽 계정 설정 문제"로 단정하고 사용자에게 관리자 화면
(응용 프로그램 권한 / 2단계 인증 강제)을 뒤지게 만들었다. 사용자가 "응용 프로그램 권한이
안 보인다"고 되물어 준 덕에 내 코드를 다시 봤고, `session` 한 줄이었다.
→ **"설정 문제"로 넘기기 전에 내가 보낸 요청의 인자부터 문서와 대조할 것.**
   버전을 바꿔도 결과가 똑같으면 바뀐 적 없는 **다른 인자**가 범인이다.

## ⛔ 같은 숫자가 API마다 다른 뜻이다 — 한 표로 합치면 안 된다

`_ERRS_COMMON`(100~119) / `_ERRS_AUTH` / `_ERRS_FS` 를 **따로** 둔 이유:

| 코드 | `SYNO.API.Auth` | `SYNO.FileStation.*` |
|---|---|---|
| 400 | 아이디/비밀번호 틀림 → **쌓이면 이 PC의 IP 차단** | 파일 작업 인자 오류 |
| 402 | 계정 권한 없음 | NAS가 너무 바쁨 |
| **407** | **IP 차단됨** | **권한 없음(폴더 ACL 거부)** |
| 411 | 계정 잠김 | 읽기 전용 파일시스템 |

합쳐 뒀더니 권한 없는 팀 폴더를 조회할 때 FileStation의 407이
**"이 IP가 차단되었습니다"** 로 찍혔다 — 차단된 적도 없는데 차단됐다고 보고한 셈이고,
사람을 엉뚱한 복구 작업으로 보낼 문구다. `_msg(code, api)` 에 **api 를 반드시 넘길 것.**

로그인 실패 대응 규칙:

| 코드 | 쌓이면? | 대응 |
|---|---|---|
| **400** | **이 PC의 IP 차단**(계정이 아니라 PC 전체) | 1회 후 영구 중단, 사람에게 넘김 |
| **402** | 비밀번호 카운터에 안 쌓임 | **먼저 내 요청 인자를 의심**(위 session 사고) |
| 403/404/406 | — | OTP 코드를 사람에게 받아 1회 더(재시도 아님) |
| 407 / 411 | — | 즉시 중단 |

`_BLOCKED`(nas_dsm.py)는 한 번 실패하면 **사람이 설정을 다시 저장할 때까지 잠근다** —
그룹웨어·SAP·인사관리에 이미 깔아둔 것과 같은 규칙.

## ✅ 팀별 ACL은 실제로 작동한다 (2026-11-03 실측)

이게 이 작업의 핵심 질문이었다 — "앱이 숨기는 게 아니라 NAS가 막아 주는가". 막아 준다.

- 계정이 보는 공유는 **3개**. 그중 **쓰기가 되는 건 1개**뿐(나머지는 읽기 전용, posix 555)
  → 앱 데이터는 쓰기 가능한 공유에 둬야 한다. 공유 목록부터 계정별로 다르다
- 개발팀별 폴더 12개 중 **본인 팀 + 공통 폴더만 열리고 8곳이 거부**(FileStation 407)
  = 지금 Drive 상태(누구나 전 팀 열람)와 **근본적으로 다르다**
- 권한 없는 공유는 **목록에 아예 안 나온다**. 권한 없는 하위 폴더는 **보이지만 열면 407**
  → 목록 코드는 "보이는 것"과 "열 수 있는 것"을 구분해야 한다

⚠️ 그래서 `_listProjectFiles` 를 그대로 옮기면 **ACL을 켜는 순간 터진다** — 지금은 한 폴더가
   막히면 통째로 실패한다. 거부된 폴더를 **건너뛰고 계속**하게 고쳐야 한다.

## ⚡ 속도 — 고정비가 전부다 (2026-11-03 실측)

폴더 목록 시간 ≈ **(왕복 고정비) + (항목당 비용 × 항목 수)**. 앱 프로젝트 폴더는 수십 개라
**고정비가 체감 속도를 결정한다.**

| | 호출 1회 고정비 | 항목당 | 84KB 파일 읽기 |
|---|---|---|---|
| DSM API — 연결 재사용 **없음** | 116.3ms | 0.13ms | 132.4ms |
| DSM API — 연결 재사용 **있음** | **61.1ms** | 0.127ms | 60.7ms |
| SMB 경유 (`/doc/*`) | 44.2ms | — | 5.4 MB/s |

**연결 재사용(HTTP keep-alive)만으로 116 → 61ms, 1.9배.** 편차도 사라진다(min/max 1ms 차이).
매번 `requests.post()` 를 쓰면 **요청마다 TCP+TLS 핸드셰이크를 새로 한다** — `_http()` 가
모듈 수준 `requests.Session()` 을 들고 있는 이유다. 새 호출 경로도 반드시 `_call` 을 지날 것.

⚠️ **처음엔 244ms 가 나왔고 "SMB의 5배 느리다"고 읽힐 보고를 했다** — 항목 1,132개 폴더를
   작은 폴더의 44.2ms 와 나란히 놓은 것이었다. **같은 일을 재지 않은 비교는 숫자가 맞아도 틀렸다.**
⚠️ SMB 쪽 루트는 **다른 공유폴더**라(그 공유는 DSM 계정에 아예 안 보인다) 같은 폴더를
   양쪽으로 잴 수 없다. 비교는 **고정비끼리만** 하고, 조건을 같이 적을 것.
⚠️ 84KB 읽기의 `1.3 MB/s` 는 처리량이 아니다 — 60ms 고정비가 지배한다. 큰 파일로 다시 잴 것.

**설계 결론**: 호출 수가 곧 시간이다(61ms × N). 프로젝트 목록처럼 N번 조회하는 경로는
**병렬화하거나 한 번에 받게** 해야 한다 — 지금 Drive 경로가 `Promise.all` 로 그렇게 하고 있다.

## ⌨️ 입력 사고 2건 — 둘 다 "조용히 틀린 값이 저장됨"

- **한글 IME**: `y`가 `ㅛ`로 들어가 HTTPS가 꺼진 채 저장됐다. 포트는 HTTPS 포트라
  평문 요청이 가서 400 Bad Request — **사람은 "비밀번호 틀림"으로 읽을 수밖에 없었다.**
  같은 상태로 입력된 비밀번호는 `getpass`가 가려 주니 확인할 방법이 아예 없었다.
  → y/n은 IME 변형까지 받고 **못 알아들으면 되묻는다**(조용히 '아니오'로 넘기지 않는다),
    비밀번호는 **두 번** 받아 맞춰 보고 **한글/비ASCII 글자 수를 보여준다**(값은 숨긴 채).
- **터미널에 입력이 안 들어가는 환경**이 있었다 → `--clip`으로 타이핑을 없앴다.
  클립보드 → DPAPI 직행, 프롬프트도 명령 이력도 없고, 성공하면 **클립보드를 비운다**.
  ⚠️ `ctypes`로 Win32 클립보드를 쓸 땐 **`argtypes`를 전부 명시**할 것 —
    안 적으면 64비트 핸들이 기본 `c_int`로 넘어가 `int too long to convert`로 터진다.

## 비밀번호 취급 (그룹웨어·SAP과 같은 규칙)

- 저장은 **Windows DPAPI**(`nas_login_config.json`, .gitignore) — 같은 Windows 계정에서만 풀린다
- **POST 본문으로만** 보낸다 — GET이면 NAS의 nginx 접근로그에 통째로 남는다
- 명령줄 인자로 받는 경로는 **일부러 만들지 않았다**(명령 이력에 남는다)
- 로그·응답·예외 메시지에 싣지 않는다
- 자체서명 인증서라 `verify=False` + 경고 억제. 사설 CA가 생기면 `verify`를 켤 것
  (그래도 평문 HTTP보다는 낫다 — 전송은 암호화된다)

## 📐 1단계 배치 결정 (2026-11-03, 사용자 결정)

**팀별 파일까지 공용 폴더 한 곳**에서 운영한다. 안정화 후 팀별 파일만 팀 폴더로 이사한다.
**메일 배분은 팀 내에서만** 한다 → 배분 큐가 필요 없고, 1단계에선 ACL 거부 처리도 필요 없다.

그래서 **경로를 코드에 박지 않는 것이 이 구조의 전부**다. 설정(`nas_login_config.json`,
.gitignore)에 두 개를 둔다:

| 키 | 뜻 |
|---|---|
| `root` | 공용 루트. 앱 데이터 전부가 여기 들어간다 |
| `team_root` | 팀 파일의 부모. **비어 있으면 `root` 와 같은 곳 = 1단계** |

2단계 이사는 **`team_root` 를 채우는 것만으로** 끝난다 — `nas_set_root.py --team-root "<경로>"`.
경로를 코드에 박으면 그 이사가 99개 호출지점을 다시 여는 일이 된다.

하위 배치(`_LAYOUT`, nas_dsm.py)는 지금 Drive 구조를 그대로 옮긴 것: `_App_Config/`
`Backups/` `MailBodies/` `TaskInbox_Backups/`.

### 어디에 둘 것인가 — 공유별 실측

공용 데이터를 **본인 팀 폴더에 두면 안 된다**. 다른 팀 폴더는 서로 `posix=0`(목록조차 거부)라,
공용을 팀 폴더에 두면 **다른 팀 앱이 부팅조차 못 한다**. 공용은 전 팀이 쓰기 가능한
공통 폴더에 둔다(실측 RWAD 777).

특히 `project_index.json` — 메일을 어느 프로젝트로 보낼지 정하는 인덱스라 공용에 있어야 한다.

## ✍️ 쓰기 경로 — 원자적 교체 (2026-11-03 구현·실측)

`put(path, data)` 가 하는 일: **임시 폴더에 최종 이름으로 올리고, 대상 폴더로 `overwrite` 이동.**

⚠️⚠️ **`CopyMove` 는 파일 이름을 유지한다 — 이름을 바꾸는 기능이 아니다.**
  처음엔 `folder/name.tmp-xxx` 를 `folder` 로 옮기면 최종 이름이 될 줄 알았는데
  **자기 자신으로 옮기는 no-op** 이었다. 최종 파일이 한 번도 안 생겼는데 `put` 은 `ok` 를 돌려줬다.
  → 임시 **폴더**를 쓰고 그 안에 **최종 이름**으로 올려야 한다.

⚠️⚠️ **DSM 은 "없는 파일" 다운로드에도 502 + "페이지를 찾을 수 없습니다" HTML 을 준다.**
  위 no-op 때문에 파일이 없었고, 그 502 를 보고 **"NAS 다운로드 핸들러가 전역으로 죽었다"고
  오진했다**(공유별·한글별·연결누수까지 의심하며 한참 헤맸다). 다운로드는 깨진 적이 없었다.
  → `download()` 가 502 를 만나면 **먼저 그 경로가 있는지 묻고** 사람 말로 가른다.
  → 그 HTML 을 바이트로 돌려주면 호출한 쪽이 **그걸 파일 내용으로 저장한다**. 반드시 막을 것.

⚠️⚠️ **`getinfo` 는 없는 경로도 항목으로 돌려준다**(그 항목에 `code` 가 실린다).
  안 걸러서 `exists()` 가 **항상 True** 였고, 그래서 "썼는지 확인"도 무력했다.
  `path_info()` 에서 `code` 있는 항목을 버린다.

⚠️ **`Delete` 는 성공을 돌려주면서 안 지우는 경우가 있다**(실측: 한 공유폴더에서 코드 900).
  ACL 이 전부 허용으로 보이는데도 난다 — 불변 스냅샷·동기화 잠금 같은 **공유 단위 정책**일 수
  있으니 권한 탓으로 단정하지 말 것. `remove()` 는 지운 뒤 **확인하고**, 남아 있으면
  비동기 경로로 1회 더 시도하고, 그래도 남으면 **정직하게 실패**한다.

**세 사고 모두 "반환값을 증거로 삼았다"가 원인이다.** 그래서 `put` 은 쓴 뒤
`_verify_written` 으로 한 번 더 묻는다(한 호출 ≈ 60ms — "저장된 줄 알았는데 안 됨"보다 싸다).

### 속도 (실측, `tests/nas-write-probe.py`)

| 크기 | 원자적 쓰기(중앙) |
|---|---|
| 1KB | 348ms |
| 64KB | 346ms |
| 512KB | 477ms |

고정비가 지배한다(호출 1회 61ms × 호출 수). 그래서 호출 수를 줄였다:
**임시 폴더를 쓰기마다 만들고 지우지 않고 프로세스당 하나를 재사용**(`.ganttput-<pid>-<rand>`,
PC·프로세스끼리 절대 안 겹친다) → **543ms → 323ms**. `ensure_folder` 결과도 기억한다(`_FOLDER_OK`).
⚠️ 프로세스가 중간에 죽으면 임시 폴더가 남는다 → `cleanup_tmpdirs(folder)` (**내 태그만** 지운다,
다른 프로세스가 쓰는 중일 수 있으므로).

검증 9건 전부 통과: UTF-8 한글 왕복 · 덮어쓰기 · 임시자리 정리 · 하위폴더 자동생성 ·
**동시 쓰기에서 완전한 JSON**(반쪽 파일 없음) · 속도.

  ② **사내 공유 경로가 프런트 코드에 들어가지 않는다**(저장소가 공개라 중요하다).

  ② **비어 있고 오래된**(기본 10분) 것만 지운다 — 쓰는 중인 남의 폴더를 지우지 않기 위해서다.
  `staleSec: 0` 으로 강제해도 안전한 이유: 업로드가 `create_parents=true` 라
  남의 임시 폴더를 지워도 **그쪽 다음 업로드가 폴더를 다시 만든다**(실측 확인).

## 🔀 저장소 어댑터 (`js/57-storage-adapter.js`, 2026-11-03)

**기존 파일을 안 고쳤다.** Drive 를 부르는 자리가 24개 파일에 흩어져 있다 — 실측으로
`googleapis` 호출 약 120곳, `gapi.client` 약 110곳. 그걸 하나하나 고치면 ① 리뷰가 불가능하고
② 지금 앱을 쓰는 사람들에게 그 변경이 **즉시** 배포된다(GitHub Pages).
그래서 호출지점이 아니라 **네트워크 경계 두 곳**만 감싼다:

| 경계 | 가로채는 것 |
|---|---|
| `window.fetch` | `googleapis.com/(upload/)drive/v3/files…` |
| `gapi.client.drive.files` | `.get` / `.list` (`about.get` 포함) |

이 둘이 Drive **데이터** 접근의 전부다. 나머지 `gapi.client` 사용(`getToken`/`setToken` 77+7곳)은
인증이라 데이터와 무관하다.

### ⚠️ 플래그가 꺼져 있으면 아무것도 감싸지 않는다
```
켜기:  localStorage.setItem('gantt_storage_backend', 'nas')  → 새로고침
끄기:  localStorage.removeItem('gantt_storage_backend')       → 새로고침   ← 비상 탈출구
```
파일은 순수 함수만 내놓고 **즉시 return** 한다. 실제 앱에서 확인한 것: 플래그 OFF 면
`window.fetch`·`window.gapi` 를 건드리지 않고 `installed=false` 다. 이게 "라이브 사용자에게
영향 없음"의 근거다.

### 📐 id ↔ 경로 — 경로가 곧 id다
Drive 는 불투명한 `fileId` 를 쓰고 앱이 그걸 **저장해 둔다**(`project_index` 의 `drive_file_id` 등).
NAS 엔 id 가 없고 경로만 있다. 그래서 id 를 경로에서 **만든다**:

- 루트 → `SHARED_FOLDER_ID` 그대로 (앱이 상수로 들고 있어 바꿀 수 없다)
- 그 밖 → `nas_` + `d`|`f` + `_` + base64url(상대경로)

**id 대장을 따로 들지 않는다** — 들면 그게 또 꼬인다. 이름도 **그대로** 쓴다(Drive 이름 = NAS 이름).
이름을 바꾸면 "앱이 부르는 이름"과 "NAS 에 있는 이름"이 어긋나는 사고가 반드시 난다.

### ⚠️ 모르는 질의를 무시하면 "조용한 오답"이 된다
`q` 파서는 앱이 실제로 쓰는 문법만 받는다(`name=` · `mimeType=`/`!=` · `'ID' in parents` ·
`trashed=false`, AND 로 이어지고 parents 만 OR 묶음). 모르는 절은 **무시하지 않고 오류로 던진다** —
무시하면 조건을 덜 걸고 **전건을 돌려주는** 것이 되고, 그건 오류보다 나쁘다.
문자열 리터럴을 먼저 빼내고 자리표시로 바꿔 쪼개므로 `name='a and b.json'` 도 안전하다.

### ⚠️ `gapi.client.init` 이 우리 stub 을 덮는다 — 세 겹으로 막았다
`gapi.client.init({discoveryDocs})` 가 나중에 `gapi.client.drive` 를 다시 심는다.
그 사이가 **조용히 Drive 로 나가는 창**이 된다. ① `defineProperty` getter 로 못 덮게 ②
`intializeGapiClient` 를 감싸 초기화 직후 다시 심기 ③ 1초 간격 백스톱.

### 권한 거부 폴더는 건너뛴다
`files.list` 가 여러 부모를 받을 때, 한 폴더에서 권한 오류가 나면 **그 폴더만 건너뛰고 계속**한다.
통째로 실패하면 목록이 0건이 된다 — 팀별 폴더는 서로 열람 권한이 없는 게 정상이다.

### 지금 안 되는 것 (솔직하게)
- **`/copy`** (백업의 서버 복사 빠른 길) — NAS 엔 없다. 앱이 **직접 업로드로 폴백**하는 구조라
  실패가 정상 동작이다. 그래서 `expected` 로 표시해 콘솔 경보를 만들지 않는다.
- **`/export`** (참조 Google 시트 내보내기, 1곳) — NAS 로 옮길 수 없는 것이다. 막는다.

### ⚠⚠ 실제로 돌려 보고 잡은 것 (2026-11-03, 연결부 1차 실행)

번역기 52/0 이었는데도 **앞 경로로 한 번 돌리자마자 버그 둘이 나왔다.** 둘 다 번역기 밖에 있었다.

1. **앱 루트 목록이 400 이었다 — 이게 제일 크다.**
   `_nas_target` 이 빈 `rel` 을 거절했는데, `_listProjectFiles` 는 **루트 직속** 프로젝트
   파일을 읽는다. 그대로 켰으면 프로젝트 목록이 통째로 비었을 것이다.
   → 읽기(`list`/`get`)와 `sweep` 만 `allow_root=True`. **쓰기·폴더생성·삭제는 그대로 거부** —
   빈 rel 을 삭제에 허용하면 **앱 데이터를 통째로 지운다.**

   ⚠⚠ **더 나쁘걸 어댑터가 했다** — 그 400 을 'ACL 거부'로 보고 **조용히 건너뛰었다.**
   결과는 오류가 아니라 **빈 목록**이었다. 내가 막으려던 바로 그 "조용한 오답"을
   내가 만들었다. → 건너뛰는 건 **403 만**, 400/500 은 던진다.
   (교훈: "에러나면 건너뛰기"는 안전해 보이지만, **어떤 에러인지 안 가르면** 안전장치가 아니라 은폐막이다)

2. **`new Response('', {status:204})` 는 TypeError 를 던진다** — 204 는 본문을 가질 수 없고
   빈 문자열도 본문으로 친다. **삭제는 실제로 됐는데** 그 뒤에서 터져 "500 실패"로
   보고됐다. `null` 이어야 한다.

3. (사소) 모르는 `q` 절 신고 문구에 **내부 자리표시가 그대로** 새어 나왔다
   (`fullText contains  0 `). 신고는 사람이 읽을 수 있어야 쓸모가 있다.

→ 세 개 모두 하네스에 회귀 케이스로 박았다(라우트 25/0, 번역기 54/0).
